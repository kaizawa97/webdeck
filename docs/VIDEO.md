# VIDEO.md — レンダ動画スライドの制作規約

HTML + GSAP で組んだ composition を **HyperFrames** で mp4/webm に焼き、`<video>` としてデッキに埋め込む
ための正典。**動画を作るときだけ開く**。既存の静止面に時間軸を足す in-slide アニメ(CSS keyframes)は別物で、
規律も検証も違う — `docs/ANIMATION.md` を読むこと。

動画は改修コストが高い。1本直すと再レンダ・ポスター再抽出・継ぎ目再実測・台帳更新が連鎖する。**その連鎖を
引き受ける価値があるか**を §1 で決めてから着手する。

---

## 1. いつ動画にするか

**静止画では表現不可能な世界を見せるときだけ**作る。座標空間・変換・3D 投影・粒子のように「そこにレイアウト
が無い」ものを作る場合である。この時デッキ地色と別の背景(暗い箱など)を許すと、「ここは別の世界=概念の
可視化」という枠づけが同時に効く。逆に**既存の静止面に「順序」を足したいだけなら動画にしてはならない**。
それは in-slide で足せる — 静止面を 1px も変えずに済み、配布物も無損失で、検証結果も不変のままになる。動画は
その利点を全部失う。

「時間構造を持つ面かどうか」の門と、動画 / in-slide の媒体選択の判断軸は `docs/ANIMATION.md` に正典がある。
**先にそちらで媒体を決める**こと。後から乗り換えると継ぎ目・配布・検証の前提が全部変わる。

混在デッキでは、動画キャンバスを**「窓」として扱う**と地色の違いが破綻しない。角丸+影を付けた矩形をスライド
側(HTML)で作り、その中に `<video>` を敷く。同じ窓意匠を in-slide の SVG 面にも流用すると、動画面と静止面が
同じ語彙で並ぶ。あわせて**色を装飾ではなく意味に割り当て、全系統・全ビート・スライド本体まで通す**(人間の
言葉 / 機械の内部表現 / 環境・道具 / 答え・着地 のような役割に色を固定する)。ある動画で学んだ読み方が別の
動画でもそのまま効き、「別々の動画」が「一本の説明」に見える。色は最初に決め、途中で足さない。

## 2. セットアップ

HyperFrames は**外部 npm パッケージ**であり、このプラットフォームの依存には**含めない**。デッキにビルド
ステップを持たせない方針(`docs/AUTHORING.md` §7)を崩さないため、**npx でバージョンを固定して呼ぶ**。
devDependency にもしない。

```bash
HF="npx --yes hyperframes@0.7.5"     # 動作確認済みのバージョンを固定して呼ぶ
$HF doctor                            # Chrome/ffmpeg 等の依存チェック(初回に1度)
```

初回のみネットに出る。以後は npx キャッシュに実体が残るので、オフラインで速く回したい時は
`node <キャッシュ>/node_modules/hyperframes/dist/cli.js` を直叩きしてもよい(パスは環境依存)。使うサブ
コマンドは実質5つ。`snapshot` / `render` の `DIR` は **project dir**(`index.html` のある所)で、省略時はカレント。

| コマンド | 用途 |
|---|---|
| `init <name>` | composition プロジェクトの雛形生成 |
| `snapshot [DIR]` | 指定秒のフレームを PNG 化(フレーム QA の主力) |
| `render [DIR]` | mp4 / webm 等へ書き出し |
| `lint [DIR]` / `validate [DIR]` | 静的検査 / headless Chrome で読み込んで console エラー報告 |

雛形を1つ作ったら、**以降のビートはその雛形を `cp -r` して作る**のが最短である。プロジェクトに入るのは
`index.html`(composition 本体)/ `meta.json`(`id` と `name`)/ `hyperframes.json` / `package.json` /
`_assets/`。`snapshots/` と `renders/` はコマンドが作る。

## 3. パイプライン全体像

```
① 1ビート = 1プロジェクト(index.html が composition 本体)
② 共有アセット(スタイル / GSAP / フォント)を各プロジェクトへコピー同梱
③ snapshot で節目を静止画化 → コンタクトシートを目視 → QAログ → 修正(v1→v2→v3)
④ render で mp4(主) + webm(副) を出力
⑤ 完成形フレームからポスター PNG を抽出
⑥ デッキへ統合(ビート積層 + 1クリック=1ビート自動再生)
⑦ 尺・ポスター・継ぎ目を台帳に実測記録
```

③〜⑦ は独立していない。**④に戻ったら⑤⑥⑦を必ずやり直す**(§12)。

## 4. 1ビート = 1プロジェクト

`snapshot` は**プロジェクトの `index.html` のみ**を対象にする(composition を選ぶ `-c` が効くのは `render`
だけ)。したがって「**ビートごとに独立した動画ファイル**」と「**ビートごとの静止画 QA**」を両立する最も素直な
形が、1ビート = 1プロジェクトになる。

副作用として重要なのが**アセット参照の制約**である。レンダ用サーバは**プロジェクト root を配信ルートにする**
ので、`../` で上位の共有ファイルは読めない。共有スタイル / ライブラリ / フォントは各プロジェクトの
`_assets/` に**コピー同梱**して `./_assets/…` で参照し、**共有元を編集したら同梱を再同期する**(忘れると
「直したのに反映されない」で必ず溺れる。同期は1本のシェルスクリプトにして編集のたびに叩く)。外部 CDN は
使わない。GSAP は決定論のため**ローカル同梱**する。

## 5. composition オーサリング規約

1つの composition = 1つの自己完結 HTML。ルート要素とタイムライン登録が契約になる:

```html
<div id="root" data-composition-id="<id>" data-start="0" data-duration="<秒>"
     data-width="1280" data-height="720">
```
```js
var tl = gsap.timeline({ paused: true, onUpdate: renderTick });  // 必ず paused
window.__timelines["<id>"] = tl;                                 // ランタイムが任意秒へ seek
```

出力は `data-width` × `data-height`、既定 30fps。デッキのキャンバスと揃えて 1280×720 にする。

**決定論の鉄則** — `Date.now()` / `Math.random()` / ネット fetch は**禁止**。レンダは「停止したタイムラインを
seek して1フレーム撮る」の反復なので、非決定要素があるとフレーム間で世界が飛ぶ。乱数を使わない JS ループ
(格子生成など)は問題ない。

**レイヤの役割分担** — **テキストは HTML レイヤ**(フォント制御が確実)、**点・矢印・図形は SVG レイヤ**
(座標が正確)のハイブリッドが最も扱いやすい。SVG 内で `transform` を使うときの座標系の型は
`docs/ANIMATION.md` に正典がある(素朴に `scale` を書くと要素が飛ぶ)。

**3D を混ぜる場合**も土俵は同じにする。①アニメ値は **proxy オブジェクト**(カメラの球面座標、点スケール等)に
持たせて GSAP でトゥイーンする。②**timeline-level の `onUpdate` を唯一の描画関数**にする(`onUpdate` は seek
でも発火する) — proxy を読んで 3D オブジェクトへ反映 → `render()` → HTML ラベルは 3D→2D 投影して
`left`/`top` を更新。③**落とし穴**: proxy を経由せず 3D オブジェクトのプロパティを直書きすると、毎フレームの
描画関数が**それを上書きして無効化**する。全アニメ値を proxy に統一する。④クリアカラーは**不透明**に設定する
(§7 の透過の罠と同根)。ライブラリは **classic script で読める UMD 配布**を選ぶ(`docs/AUTHORING.md` §7 で
ESM は禁止)。GPU が無い環境ではソフトウェアラスタライザに自動フォールバックする(強制は `--browser-gpu` /
`--no-browser-gpu`)。

**品質原則** — 最終成果物が動画なので in-slide の「既定値 = 完成形」規律は**適用外**で GSAP を自由に使えるが、
代わりに **①段階数(最低3状態の遷移) ②意味性(動きが概念を説明している) ③イージング使い分け(最低3種)
④線のドロー ⑤レイヤ深度**を必達にする。

## 6. フレーム QA

```bash
$HF snapshot . --at 0.7,1.6,2.9,3.6,4.3,5.2,6.3,7.2,8.4 --describe false
#   -> snapshots/frame-NN-at-XX.Xs.png と contact-sheet.jpg
```

- **`--at` は1回にまとめて指定する**。snapshot は毎回 `snapshots/` を作り直して連番を振り直すため、後から
  単発で `--at` を足すと**直前のバッチが消える**。等間隔の `--frames N`(既定5枚)もあるが、動きの節目を狙う
  ので秒指定のほうが実用的で、決定論なので修正前後の比較にそのまま使える。
- `--describe` は既定で外部ビジョン API に問い合わせる。**`--describe false` で切る**(ネット依存を作らない・
  出力を安定させる)。
- **`contact-sheet.jpg` を画像として実際に読む**。見るのは「重なり / タイミング / 読めない文字 / 唐突な動き /
  イージングの不自然さ / **動きが概念を説明しているか**」。細部は個別 PNG を開く。
- 所見は `[重要度] 症状 → 原因 → 対策` 形式で QA ログに残し、**v1→v2→v3 と回す**。ログは「同じ指摘の再生産」を
  止める資産になる(後のラウンドで「その指摘は旧版前提」と即断できる)。

`lint` の警告のうち、CSS 変数を解決できないことによるフォント警告は**偽陽性**である。`snapshot` / `render` の
ログに `Fonts loaded: …` が出ていればフォントは実際に読めている。`--strict`(lint エラーで失敗)/
`--strict-all`(警告でも失敗)を付けなければレンダは通る。**偽陽性と判定した根拠はその場で書き残す**。書か
ないと次のラウンドで「未修正の欠陥」に見える。

## 7. レンダ出力と透過の罠

```bash
$HF render . --format mp4  -q high -o renders/<name>.mp4    # 主(不透明・互換性最良)
$HF render . --format webm -q high -o renders/<name>.webm   # 副(VP9)
```

`-q` は `draft` / `standard` / `high` で、本番書き出しは `high`。`--docker` を付けると Chrome とフォントが
固定され、マシン非依存の完全再現になる。

**`--format webm` は既定で透過(alpha)になる。この時 `html`/`body`/ステージの CSS 背景は omit されて抜ける。**
静止画 QA では背景が写るのに動画だけ透ける、という食い違いが起きる。

- **対策**: composition の SVG 先頭に、**不透明な背景矩形を描画要素として置く**
  (`<rect width="1280" height="720" fill="<地色>">`)。描画要素は omit されないので mp4 / webm の両方が不透明で
  焼ける。白以外の面に重ねたい時だけ背景矩形を外して透過 webm を使う。
- **検証は角画素の実測で行う**。「角が意図した地色か」を数値で確認する:

  ```bash
  ffmpeg -y -v error -i renders/<name>.webm -frames:v 1 -vf crop=4:4:0:0 corner.png
  # corner.png の RGB を読み、意図した地色と一致することを確認
  ```
- 注意: **ffmpeg の overlay は VP9 alpha を復号しない**(黒く見える)。不透明化した出力なら1フレーム抽出で
  地色を確認できる。ブラウザの `<video>` は VP9 alpha を正しく扱う。

## 8. ポスター

各 `<video>` に `poster` を付ける。ファイル名は**動画 basename と一致**させる規約にすると対応漏れが起きない
(`<name>.mp4` ↔ `<name>-poster.png`)。解像度は動画と同一にする。

**選定基準は「そのビートの主題が最も読める瞬間」**である。冒頭の空白と遷移中は避ける。多くは終盤の完成形だが、
**終端はその近似にすぎない**。終端が「次ビートへの受け渡し形」になっているビートでは、標題と図が揃う中盤の
ほうが読める — その場合はそこを採る。

```bash
ffmpeg -y -v error -ss <秒> -i renders/<name>.mp4 -frames:v 1 renders/<name>-poster.png
```

終端フレームを採る場合はフレーム番号で指定する(`nf` の求め方と `select=eq(n,…)` は §11.2 と同じ)。
**動画を再レンダしたらポスターも必ず再抽出する**(§12)。

## 9. デッキ統合 — ビート積層

```html
<!-- --pp = 最終ビートのポスター(印刷時に敷く) -->
<div class="stage" style="--pp:url('assets/anim/posters/<最終ビート>-poster.png')">
  <video class="beatvid" data-beat="1" data-autoplay muted playsinline preload="auto"
         poster="assets/anim/posters/<ビート1>-poster.png"
         aria-label="ビート1: 何がどう動いて何を示すかを文で説明する">
    <source src="assets/anim/<ビート1>.mp4" type="video/mp4">
  </video>
  <span class="beatwrap fragment" data-fragment-index="0">   <!-- 2本目以降: ラップの子に video -->
    <video class="beatvid" data-beat="2" muted playsinline preload="auto" poster="…" aria-label="…">
      <source src="assets/anim/<ビート2>.mp4" type="video/mp4">
    </video>
  </span>
</div>
```
```css
.beatwrap { position: absolute; inset: 0; }                    /* 前ビートを不透明に覆う */
.beatvid  { position: absolute; inset: 0; width: 100%; height: 100%;
            object-fit: contain; background: var(--stage-bg); }
@media print {   /* 配布物は完成形の静止画: ポスターを敷き video を隠す */
  .stage { background: var(--stage-bg) var(--pp) center / contain no-repeat !important; }
  .stage .beatvid { display: none !important; }
}
```

- **後続ビートは絶対配置で前ビートを「不透明に覆う」**。切り替えではなく被せなので、前ビートの終端フレームが
  下に残っていても事故にならない。
- **fragment のラップは `<span class="beatwrap fragment">` にし、その子に `<video>` を置く**。スライドランタイム
  は fragment 表示時に**子孫の自動再生対象を再生する**。video 自身に `fragment` を付ける形にすると再生トリガが
  噛まない。**`data-autoplay` は先頭ビートだけ**。
- **ビートインジケータ(●○○)**を同じ `data-fragment-index` で連動させると、聴衆と登壇者の両方に「いま何拍目 /
  あと何拍」が伝わる。**キャプションの後半も同 index の fragment で伏せる**(ネタバレ防止)。ただし opacity で
  隠した fragment も**レイアウトは占める**ので、キャプション行の高さは最初から確保されている前提で組む。
- **`aria-label` に「その動画が何を見せているか」を文で書く**。動きは代替テキストがないと完全に失われる。

## 10. 再生制御 — 1クリック = 1ビート

- **スライド到達** → 先頭ビートを自動再生。後続ビートは**完成形フレームで静止して待機**。
- **ビート終了** → 終端フレームで静止 → **数秒 HOLD → 頭から再ループ**。次へを押すまでこれを続ける。デッキに
  「もう一度再生」の UI が無いため、**ループが唯一の再視聴手段**になる。ループするのは常に**見えている最上位の
  1本だけ**。
- **次へ** → 次ビートを表示 = 再生開始(前ビートのループは自動停止)。**戻る** → 隠れたビートは静止、直上の
  ビートをループに戻す。**スライド離脱** → ループ停止・全ビート完成形静止。

```js
var EPS = 0.05, HOLD = 3000;
var RM = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
function seekEnd(v){ v.currentTime = Math.max(0, v.duration - EPS); }
function atEnd(v){ v.pause(); v.onended = null; seekEnd(v); }       // 完成形で静止
function loop(v){
  if (RM) { atEnd(v); return; }                                    // 省モーション: ループしない
  v.onended = function(){
    v.pause(); seekEnd(v);                                         // 明示 pause + 終端へ seek
    holdTimer = setTimeout(function(){ playFromStart(v); }, HOLD);
  };
  playFromStart(v);
}
```

- **`ended` で最終フレームが表示され続ける保証はない**。明示 `pause()` + 終端へ `seek` する。`EPS`(数十 ms
  手前)を引くのは、ちょうど終端だと最初のフレームへ巻き戻る実装差を避けるため。この「終端 = ポスター =
  完成形」の三点一致が、継ぎ目と配布物の両方を支えている。
- **省モーション / 印刷では、ループせず全ビートを完成形で静止させる**。これで自動検証(スクリーンショット
  比較)と PDF 出力の結果が**再生タイミングに依存しなくなる**。
- **動画ビート面では fragment の自動送りを禁止する**。通常スライドで fragment を自動送りする仕組みを入れて
  いる場合、「動画面かどうか」で分岐しないとビートが勝手に飛ぶ。ユーザーが操作(クリック / キー)したら自動
  送りを止める(二重送り防止)。

## 11. 継ぎ目(マッチカット)

1枚のスライドに複数の動画を積むと、**ビートの切り替わりが「カット」として見える**。聴衆には「別の動画が
始まった」と映り、そこで理解の連続性が切れる。系統をまたぐ場合(あるスライドの最終動画 → 次スライドの最初の
動画)はもっと悪い。目標は**全ビート・全系統を通して一本の説明に見せる**ことで、そのための技術が
**マッチカット**である。

### 11.1 アンカー要素で判定する

継ぎ目の一致は**全画面の画素一致ではない**。それを目標にすると永久に達成できない(タイトルやキャプションは
ビートごとに違って当然、アンビエント粒子は毎フレーム動いて当然)。代わりに継ぎ目ごとに**アンカー要素**を
1〜2個定義する。アンカーとは「そのビートから次のビートへ引き継がれるべき主要素」であり、**聴衆が視線を置いて
いる対象そのもの**である。空間図なら意味色でマスクした点群の重心と bbox、文を育てる系なら文ヘッダの bbox
左右端とベースライン、構造図のモーフなら引き継ぐボックス群の中心。系統をまたぐバトンでは両系統に共通して
現れる要素を採る。

- **受け入れ基準: アンカーの座標差 ≤1px かつサイズ一致。**
- **全画面差分は補助指標としてのみ併記し、必ず内訳を分類して書く**:

  > 全画面 diff の内訳 = アンカーのアンチエイリアス / アンビエント粒子(装飾) / 下部キャプション
  > (**マッチカット対象外の可変テキスト**)。→ 一次アンカーはサブピクセル一致 = PASS。

  内訳を書かないと、次のラウンドで誰かが全画面差分の数字だけを見て誤って FAIL 判定する。
- **重心差より bbox 差を信じる**。重心は画素数差(アンチエイリアス)で 0.1〜0.5px 揺れるが、bbox の左右端は
  位置そのものを表す。「bbox 完全一致 + 重心 0.4px」は exact と判定してよい。
- 幾何以外も見る。継ぎ目チェックリストは **①アンカー座標 ②アンカーサイズ ③α / 塗りの階調 ④地色の角画素**
  の4点である。座標が合っていても α が不連続だと「箱がポップする」。

### 11.2 測定手順

```bash
# 前ビートの最終フレームと次ビートの先頭フレームを PNG 化
nf=$(ffprobe -v error -select_streams v:0 -count_frames \
       -show_entries stream=nb_read_frames -of csv=p=0 prev.mp4)
ffmpeg -y -v error -i prev.mp4 -vf "select=eq(n\,$((nf-1)))" -frames:v 1 prev-last.png
ffmpeg -y -v error -i next.mp4 -vf "select=eq(n\,0)"         -frames:v 1 next-first.png
# 意味色マスクでアンカーを抽出 → 重心と bbox を比較
```

- **必ず出荷実ファイルで測る**(ソースやスナップショットではなく、デッキの `assets/` に置いた実物)。再ステージ

### 11.3 作り方の3様式

**様式A: 継承コピー + クロスフェード**(最も汎用)。次ビートの frame0 に、前ビート終端の要素を **CSS で 1:1 に
再現したコピー**を置き、0.4秒程度そのまま保持してから本要素へクロスフェードする。**二重像を避ける鉄則**は
コピーと本要素の**位置・サイズ・字送りを完全に揃える**こと(ずれると切り替わりの瞬間に文字が2枚重なって
見える)。そして**薄い要素も省略しない** — frame0 のコピーには前ビート終端で**見えている全要素**を入れる。
「うっすら見えるガイド線だから省略」で済ませると、そこだけが差分として残る。**薄い線 1 本の有無だけで**継ぎ目差分は
桁で変わる。

**様式B: 真の凍結フレーム**(最上位)。次ビートの frame0 が前ビート終端と**画素一致**していて、そこから動き
出す。系統をまたぐバトンでも到達可能である。

**様式C: ポスター一致**(弱い形・許容だが目標にしない)。次ビートは frame0 が空白で、途中で前ビート終端形に
到達する。`poster` にその時点のフレームを使うので**静止状態では繋がって見えるが、再生すると繋がらない**。演出
上の理由があれば許容するが、台帳に「**これはポスター一致であって凍結フレームではない**」と明記する。書かないと
後続ラウンドが「PASS」だけ見て安心する。

### 11.4 中間だけ変えれば継ぎ目は無風

これが**改修コストを桁で下げる**最重要の運用原理である。

> 継ぎ目が見ているのは **frame0 と終端フレームだけ**である。したがって frame0 と終端を不変に保ったまま中間
> だけ変更すれば、**継ぎ目は再実測しても PASS のまま**。

- **尺は延長してよい**。frame0 / 終端を触っていなければ継ぎ目は不変である。**図も足してよい** — 追加要素を
  **アンカーの帯の外**かつ**アンカーの色でない**ところに置けば bbox は不変 = 0px を保てる。
- **逆に、終端の意味を変える改修は継ぎ目を壊す**。「このビートの終端が意味的に弱い」という指摘が来ても、終端を
  変えると下流の継ぎ目が全部崩れる。終端を維持したまま、宙吊りのまま次ビートが答える物語として成立させ
  られないかを先に検討する。変えるなら**下流 frame0 の作り直しと再実測までを1セットで見積もる**。
- **ビートの分割は「尺の調整」ではなく「継ぎ目の新設」である**。「速すぎて追えない」等で1本を2本に割ると
  新しい継ぎ目が生まれる。新継ぎ目の実測まで含めて完了とし、分割で孤児になった旧アセット(旧動画・旧ポスター)
  は参照解除して整理する。

### 11.5 継ぎ目 ID と台帳

各継ぎ目に固定 ID を与える(J1, J2, …)。ID があると「J4 は維持」「J5 は旧測定で FAIL、修正後 0px」が会話で
通る。台帳には **アンカー / dcx / dcy / サイズ / 判定 / 一言**を必ず持たせ、測定を繰り返すたびに**履歴として
追記する(上書きしない)**。「初回 FAIL → 片側寄せで修正 → 再測定 0px PASS」という経過が残っていることが、
同じ失敗の再生産を止める。

## 12. 3つの台帳

動画は「作って埋めたら終わり」ではない。尺・ポスター・継ぎ目が他の成果物と結合していて、再レンダのたびに壊れる
場所が決まっている。だから**一次情報を台帳に固定する**。

| 台帳 | 一次情報 | 何と結合しているか |
|---|---|---|
| **尺台帳** | `ffprobe` の実測値(記述値ではなく) | 登壇ガイドの時間配分・スライド送り・合計尺 |
| **ポスター台帳** | 採用フレーム番号 + 選定理由 | PDF/PPTX の見た目・低速回線・初期表示 |
| **継ぎ目台帳** | アンカー要素の px 実測 | ビート間・系統間のマッチカット(§11) |

- **尺は必ず実測する**(`ffprobe -v error -show_entries format=duration -of csv=p=0 <name>.mp4`)。設計値・
  記述値は必ずずれる(記述値と実測値は秒単位で乖離しうる)。台帳に「**実測が正典**」と書く。尺が
  変わったら**下流の時間配分を再同期する必要があるか**を明示的に判定し、台帳の注記に「誰が同期するか」まで書く。
- **再レンダしたら: 尺再実測 → ポスター再抽出 → 継ぎ目再実測 → 3台帳更新、が1セット。** どれか1つ飛ばすと、
  後のラウンドで「PDF だけ古い」「ガイドの秒数だけ古い」が発覚する。

## 13. 運用

**単一オーナー原則** — アニメ資産は**継ぎ目で相互依存している**。あるビートの終端を触ると次ビートの frame0 が
壊れる。したがって **1系統(継ぎ目で連鎖する一群)= 1オーナー**とし、並行編集を許さない。他人の担当範囲に修正が
必要なら**直接編集せずメッセージで依頼する**。沈黙したエージェントの後継を立てる時は**先に停止させる**(復活すると
並行編集になり、継ぎ目が破損する)。

**発注書に書く5点** — ①その面が伝えたい一文(合否の基準になる) ②どの構造か(順序 / 因果 / 成長 / ループ /
緩急)と、動画で作るという媒体指定 ③不変条件(省モーション / 印刷で完成形が出る・1クリック = 1ビートの UX)
④継ぎ目の上流 / 下流のアンカー要素と許容差 ⑤完了条件(下記)。

**完了チェックリスト**

- [ ] その面が伝えたい一文が、動きだけで第三者に伝わった
- [ ] 追える速度(読む対象があるステップの滞在時間を実測)・死に間がない・終端が乱れない
- [ ] 方向を持つ要素が全部同じ向き(**その面の全モーションを棚卸し**して確認)・文字と動く要素が交差しない
- [ ] 決定論(乱数 / 時刻 / ネット無し)・角画素が意図した地色
- [ ] mp4(主) + webm(副) + ポスター(basename 一致)
- [ ] 継ぎ目のアンカーを**出荷実ファイル**で実測し台帳に記録(≤1px)
- [ ] 尺を `ffprobe` で実測し台帳更新、**下流(登壇ガイド等)の再同期の要否を判定**
- [ ] 再レンダしたら ポスター再抽出 + 継ぎ目再実測 + 3台帳更新 の1セットを完了
- [ ] 孤児アセット(差し替えで参照されなくなった動画 / ポスター)を整理
- [ ] fragment ファイルと本体の **CSS が同期している**(古い断片の CSS が巻き上げられると本体が退行する)
- [ ] 統合後に**配布実物でライブ実測**(ビート再生・終端静止・ループ・戻り)、省モーション / 印刷で全ビートが
      完成形静止になる

機械的な検証は**違和感を検出しない**。検証スクリーンショットは動画スライドでは当てにならず、**動画はフレーム
抽出で確認する**。三層検証(制作者のフレーム QA / 機械ゲート / 独立 QA)の正典は `docs/VERIFICATION.md`。
