# ANIMATION.md — in-slide アニメの原則

既存の静止スライドを **1px も変えずに時間軸だけを足す**ための正典。
面に動きを付けようと思ったときに読む。

- 静止面そのものの技術規約は [AUTHORING.md](AUTHORING.md)(§5 の「CSS アニメーションも
  同じ規律」が本書の要約にあたる)
- 専用キャンバスでレンダした動画(mp4/webm)をスライドに敷く方式は [VIDEO.md](VIDEO.md)
- 検証手段の正典は [VERIFICATION.md](VERIFICATION.md)
- コマンド中の `$PP` はスキル本体のディレクトリ(SKILL.md 冒頭の定義)

---

## 1. 適用の門 — 作るかどうかを先に決める

静止スライドは**同時に存在するもの**を語るのが得意で、**順番に起きること**を語るのが苦手。
アニメを足す判断は「見栄え」ではなく、**その面の理解の核が時間構造を持つか**で決まる。

| 時間構造 | 何が伝わらないと困るか | 典型 |
|---|---|---|
| **順序** | どれが先でどれが後か | 逐次生成、パイプラインの段 |
| **因果** | A が起きたから B になった | 選択が結果に反映される過程 |
| **成長/変換** | 同一物が別の姿になった | 語→数値→点、ランダム→構造 |
| **ループ** | 出力が次の入力に戻る | 反復・自己回帰 |
| **緩急(密度)** | 「最近に集中している」 | 年表の実日付間隔 |

**効かない構造**: 並列比較・分類・定義・引用。ここに動きを足すと装飾になり、
視線を散らして理解を落とす。

**門の判定を1行で**: 「この面は、静止画2枚を並べれば済むか?」——済むなら作らない。
「途中の変化そのものが主張」なら作る。

**作らない判断も成果として記録する**。設計メモに候補面を全部並べ、採用と見送りを理由付きで残す。
理由が無いと同じ面が何度も再検討され、「なぜここは静止なのか」にも答えられなくなる。
見送りは怠慢ではなく判断である。

## 2. 媒体の選択 — in-slide か動画か

同じ「動き」でも実装媒体が2つある。**この選択を先に決める**。後から乗り換えると
配布・検証・改修の前提が全部変わる。

| 軸 | **in-slide アニメ**(CSS keyframes) | **レンダ動画**([VIDEO.md](VIDEO.md)) |
|---|---|---|
| **情報密度** | 低〜中。既存レイアウトの要素を数個動かす | 高い。十数要素の同時運動・3D・粒子・カメラ |
| **背景** | スライド地色そのまま。既存面に溶け込む | 専用キャンバス。デッキと別の世界を持てる |
| **尺** | 数秒(到達して数秒で完成形に着地) | 数秒〜十数秒。複数ビートで数十秒まで |
| **配布(PDF/PPTX)と改修コスト** | **終端=元の静止面**なので焼いても無損失。CSS のみで直せる | ポスター静止画に焼く(動きは失われる)。再レンダ+再ステージ+ポスター再抽出が1セット |

- **既存の静止面に「順序」を足したいだけなら in-slide**。作るのは新しい絵ではなく、既にある絵の
  **到達順序**である。だから静止面を1pxも変えずに済み、これが最大の利点になる。
- **静止画では表現不可能な世界を見せるなら動画**。座標空間・変換・3D投影・粒子など
  「そこにレイアウトが無い」ものを作る場合。
- **ライト背景の通常スライドも in-slide の対象である**。「アニメ=暗背景の専用面だけ」と
  思い込むと、in-slide で安く取れる理解の跳ねを取り逃す。面数では in-slide が主戦力になる。

## 3. 五つの不変条件

これを全部満たす限り、**既存デッキのどの面にも自由にアニメを足せる**。
逆に1つでも破ると、静止面・配布物・検証のいずれかが巻き込まれる。

1. **終端 = 現行の静止完成形**。アニメが終わった画面は、アニメを入れる前と**画素一致**する。
2. **既定状態 = 完成形**。アニメが1つも走らない環境(省モーション・印刷・自動検証)でも
   完成形で静止して見える。CSS の**既定値が完成形**であり、アニメは「完成形へ至る過程」の後付け。
3. **到達で自動再生**。クリックは要らない。既存の「1クリック=1 fragment」の UX を1つも増やさない。
4. **レイアウト値は不変**。動かすのは `opacity` / `transform` / `clip-path` / `box-shadow` /
   `stroke-width` のみ。`width` / `height` / `margin` / `font-size` / `display` は触らない。
5. **尺は短い**。到達して数秒で完成形に着地し、以降は静止している。

①と②が組み合わさると強い性質が出る: **静止面が不変なので、既存の verify スクリーンショット・
PDF・PPTX の結果が一切変わらない**。検証 PNG の md5 一致を証拠として出せるので(§12)、
レビューコストがほぼゼロになる。この性質が、アニメを「安全に足せる改修」に保つ。

## 4. 実装様式

```css
/* 全体を省モーション判定で包む = 省モーション環境では1行も適用されない */
@media (prefers-reduced-motion: no-preference) {
  /* .present ゲート: 現在のスライドだけで発火。離脱→再入場で再生される */
  .reveal .slides section.present .item    { animation: fadeUp .45s cubic-bezier(.2,.7,.2,1) both; }
  .reveal .slides section.present .item.i1 { animation-delay: .10s; }
  .reveal .slides section.present .item.i2 { animation-delay: .40s; }
  @keyframes fadeUp { from { opacity: 0; transform: translateY(6px); } to { opacity: 1; transform: none; } }
}
```

- **`@media (prefers-reduced-motion: no-preference)` で包む**のが条件②の実装。
  `reduce` を打ち消すのではなく、**`no-preference` のときだけ足す**形にする。こうすると
  「アニメを消す」CSS を書く必要がなく、既定値が自動的に完成形になる。
  逆向き(既定を開始状態にして `reduce` で打ち消す)は、打ち消し漏れがそのまま
  **配布物から要素が消える**事故になる。
- **`.present` ゲート**が条件③の実装。スライド到達で `.present` が付くのでそこで発火し、
  離脱・再入場で**もう一度再生される**(登壇中に戻って見せ直せる)。
- **`animation-fill-mode: both`** が条件①の実装。終端の値が保持されるので完成形で止まる。
- **JS の `setInterval` に依存しない**。CSS keyframes なら2つのゲートがそのまま効き、決定論的で、
  検証環境やPDF出力で勝手に走らない。print view ではスライド変更イベントが発火しないため、
  JS 駆動のアニメは初期化されないまま止まる危険もある。

## 5. 重ね置き様式 — 途中状態を見せたいが静止面を変えたくない

逐次生成のように**途中の状態が複数ある**場合、素直に書くとレイアウトが変わる。解決は重ね置き:

```css
.genwrap { position: relative; }                                       /* 完成形がフローで高さを規定 */
.genstep { position: absolute; top: 0; left: 0; right: 0; opacity: 0; } /* 途中状態は絶対配置・既定不可視 */
```

- **完成形だけをフロー(in-flow)に置き、コンテナ高さを決めさせる**。
- **途中状態は絶対配置で重ね、既定 `opacity: 0`**。省モーション/印刷では途中状態が一切現れず、
  完成形だけが残る。
- 飛行トークンのような**アニメ専用要素も既定 `opacity: 0`**。これがアニメ専用要素の作法である:
  存在はするが、動かない環境では見えない。
- 逆向きも同じ原則。「アニメ中だけ**隠したい**」既存要素(飛行経路上の注記など)は
  **既定 `opacity: 1`** のまま置き、アニメ側で一時退避させて終端で復帰させる。
  既定値が完成形、という原則はどちらの向きでも変わらない。

## 6. 特異度と共用クラスの規律

ここは事故が起きやすい場所である。

- **遅延セレクタは base セレクタと同じ特異度に揃える**。
  `.reveal .slides section.present .tok.gen { animation: pop .42s both; }` に対して遅延を
  素の `.g1 { animation-delay: 1.35s }` で書くと、**shorthand が含む `delay: 0` に負けて
  全要素が同時発火**する。遅延側も `.reveal .slides section.present .tok.g1` と同じ深さで書く。
- **共用アニメクラス名は必ずスコープする**。`.d1`〜`.d5` のような汎用名を複数面で使うと、
  片方の面のアニメが**別の面に漏れる**。祖先にスライド固有クラスを置いて限定し、
  導入後に「他面へ漏れていないこと」を実測で確認する(思い込みで済ませない)。
- 無限ループのアンビエント(明滅・パルス巡回)は許容するが、**意味の運搬を
  アンビエントに担わせない**。省モーションで消えても理解が落ちない層に留める。

## 7. SVG の座標系

SVG 要素の `transform` は既定で**ユーザー空間の原点**を基準にするため、素朴に `scale` や
`rotate` を書くと要素が画面外へ飛ぶ・軌道運動する。用途別に3つの型を覚える。

| やりたいこと | 型 |
|---|---|
| 図形やグループを**中心固定で拡縮/ポップ** | `transform-box: fill-box; transform-origin: center;` |
| 棒を**下端から伸ばす** | `transform-box: fill-box; transform-origin: bottom;`(横棒は `left`) |
| **線を左から描く**(基準線・タイムライン軸) | `transform-box: view-box` + viewBox 単位の原点。`fill-box` は**零高さの bbox になって不安定** |

`fill-box` + `center` は「入れ子の段階提示」のように**多数のグループを順に出す**ケースで
軌道運動バグを一括で回避できる。導入後は `transform-origin` の計算値と実視の両面で
ドリフトが無いことを確認する。

## 8. 代表パターン集

| パターン | 実装 | 何を伝えるか |
|---|---|---|
| **時系列 pop-in** | 軸を左→右にドロー → ノードを年代順に `delay` stagger | 順序と、対象が段階的に増えたこと |
| **棒の成長** | `fill-box` + 下端 origin + `scaleY 0→1` を年代順 stagger。値ラベルは棒の完成に追従 | 「この期間で水準に到達した」 |
| **チャートのワイプ** | 画像/SVG に `clip-path: inset(… right)` を数秒で 0 へ | 「平坦が続いて末端で立ち上がる」= 変曲の劇的化 |
| **追従 stagger** | ワイプの進行に同調して過去→現在→未来の順に数値を出す。**但し書き注記は最後に置く** | 時間軸と主張の同期(誠実さも順序で表現できる) |
| **入れ子の段階提示** | 外→内へ `opacity` + 極僅かな scale-in。最後に現在地ピルを着地 | 包含関係を**出現順序そのもの**で伝える |
| **逐次生成(3拍/単位)** | ①候補が立つ →②選択が確定 →③選ばれた要素が飛んで着地(§10) | 因果連鎖 |
| **巡回パルス** | 弧に `stroke-width` + `opacity` のパルスを位相差で巡回 | 「輪が回っている」 |

## 9. 緩急で密度を語る

**間隔そのものが情報になる**。見落としやすいが、効果が最も高い型のひとつ。

- **実日付の間隔比を出現間隔に写す**: 出来事カードの `delay` を実際の日付間隔に比例させる。
  「変化はこの期間に集中している」が、説明文なしで体感される。
- **溜めて跳ねる**: 横ばいの区間はテンポを速く(目安 0.15s 間隔)、急伸する区間は溜めを増やす
  (目安 0.3〜0.4s)。間隔比が数値の跳ね方の体感になる。
- **加速リズム**: 間隔を 1.0s → 0.3s と短縮していくと「加速している」が直接伝わる。

規律: **同一スケールを守る**。棒の長さや位置を「見栄え」で調整すると誇張になる。
スケールは幾何から導出し、実測 px が数値比と一致することを確認したうえで、
**時間の演出だけを緩急に使う**。緩急は誇張の手段ではなく、正確なスケールの上に置く演出である。

## 10. 因果連鎖を省略しない(最重要)

**状態 A と状態 B を順に見せても、「A が B を生んだ」は伝わらない**。伝わるのは
「A が表示され、次に B が表示された」だけである。因果を伝えるには、
**A から B への「行為」を可視化**しなければならない。

因果を含む1単位は、最低3拍に分解する。

| 拍 | 役割 | 実装の要件 |
|---|---|---|
| **①提示** | 選択肢/材料が立ち上がる | 候補が読める時間だけ滞在する |
| **②選択** | **どれが選ばれたかの明示的な合図** | リングの確定・ラベル・強調。「なんとなく濃い」では足りない |
| **③反映** | **選ばれたものが結果側へ移動して着地** | 移動体が「同じもの」と分かる意匠を保つ |

②を省くと「勝手に決まった」に見え、③を省くと「別の場所に別のものが現れた」に見える。
**②と③が因果の本体**であり、①だけでは情報の提示にすぎない。

③を効かせる鍵は**移動体の同一性保持**である:

- 飛ぶ要素を**着地先と同じ意匠**(同じ枠・フォント・余白)で作り、着地の瞬間に本物へ引き継ぐ。
  継ぎ目が見えないまま「これがあれになった」が成立する。
- **1つずつ**飛ばす。同時に複数飛ぶと重なって同一性が崩れる。
- 軌跡は**緩い弧**にし、速度は追える範囲に収める(目安として毎秒1000px強なら中間フレームでも
  明瞭に捕捉できる)。直線・高速だと「点滅して現れた」に見える。

**終端に次のサイクルの入り口を含ませる**と、1回分の説明で反復構造まで伝わる。
完成した結果で止めるのではなく、次の周回の材料(破線の矢印・次の候補)を終端の絵に入れておく。

判定は自分でしない。**「その面が主張したい一文が、動きだけで伝わったか」を第三者に確認させる**。
作った本人の「伝わるはず」では判定できない。

## 11. 落とし穴カタログ

機械的な検証(lint・スクリーンショット比較)は**違和感を検出しない**。以下は
「人間の目でしか捕まらないが、原因は構造的」な失敗族である。

**方向を持つ要素の整合**。同じ図の中に方向を持つ要素が複数あると、1つでも逆を向いた瞬間に
「明らかにおかしい」と認識される。SVG の `circle` は**固有のパス方向(時計回り)を持つ**ので、
`stroke-dashoffset` を素朴にアニメするとその方向に走る。逆向きにするには
**dashoffset の増減方向を反転**する(`100→0` を `0→100` に)。合同なので開始と終端の見た目は
不変=静止面の不変条件は壊れない。

> **図に「方向」が現れたら、その面の全モーションの回転方向を棚卸しして統一する**。
> 1つ直して終わりにすると、残りが次のラウンドで再指摘される。矢印・リングのドロー・
> 巡回パルス・スピナーは全部同じ棚卸しの対象。

**文字と動く要素の非交差**。飛ぶ要素や伸びる矢印が文字の帯を横切ると、読めない上に汚く見える。
対策は優先順に ①軌跡を帯の外へ通す → ②帯の要素を**アニメ中だけ退避**させ終端で復帰させる
(既定 `opacity: 1` を保つので静止面は不変)→ ③その要素を動かさない。
同族の失敗として、矢印が注記を貫く・ラベルが動く点に追突する(ラベルを先回りで退避させる)。

**追える速度**。「速すぎて追えない」は最も出やすい指摘である。判定は各ステップの**滞在時間**を
実測すること(目安: 0.3s 級は追えない、0.9s 前後で追えるようになる)。対策は ①減速する
②**クリックのチェックポイントで割る**。②が効くのは、聴衆が「ここで一度止まる」と分かると
待つ姿勢になるから。逆に、要素が単純で読み順が自明なら速くても困らない
(**滞在すべきは「読む対象」があるステップだけ**)。そして**死に間を作らない** —
最後の要素が着地してから終端まで空白があると、終わったのか分からない。

**二重像と reflow**。中央寄せの行に後からトークンを足すと **reflow で既存要素が横に飛ぶ**ので、
足す要素を最初からフローに `opacity: 0` で置いて**場所を予約**する(opacity は幅を畳まない)。
重ね置きのコピーと本要素の位置・サイズ・字送りがずれると、切り替わりの瞬間に文字が2枚見える。

**marker-end の矢頭浮き**。SVG の `marker-end` は**長さ0の線でも矢頭を描く**ため、成長前の
矢頭が始点に浮く。線を `opacity="0"` にしておき、成長開始時刻に可視化する。

## 12. 検証

**終端は正常でも途中だけ壊れているバグは、静止検証を素通りする**。中間フレームを撮って見る。

```bash
node $PP/tools/anim-qa.mjs <deckDir> --slide <n> --times 0.3,0.8,1.4,2.2
```

指定秒の中間フレーム PNG とコンタクトシートが出る。**画像を自分の目で読む**
(重なり/読めない文字/唐突な動き/方向の矛盾/動きが概念を説明しているか)。所見は
`[重要度] 症状 → 原因 → 対策` の形で残す。静止面の不変は、変更前のデッキを基準に取る:

```bash
node $PP/tools/verify.mjs <deckDir> --baseline <変更前デッキdir>
```

条件①②を守っていれば、全スライドの検証 PNG が **md5 で一致**する。一致しないスライドが
出たら、それは「アニメを足したついでにレイアウトを触った」というシグナルである。

三層検証(機械ゲート/自分の目/独立監査)の設計、誤検知・盲点リスト、証明様式の詳細は
[VERIFICATION.md](VERIFICATION.md)。新しく作った面は**既存面の監査済み状態を継承しない** —
デッキ全体が PASS していても、新設面はゼロから監査する。
