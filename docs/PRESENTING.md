# PRESENTING.md — 発表・配布の運用手順

デッキの作り方は [AUTHORING.md](AUTHORING.md)。ここでは「開く・発表する・配る」を扱う。

---

## 1. ローカルで開く

デッキは呼び出し元プロジェクト側にある(SKILL.md 手順1)。開発中は、デッキと
スキル本体($PP)の**共通祖先ディレクトリ**で簡易 HTTP サーバを立てて開くのが正式
(デッキ内の `../../` 相対参照を解決するため。tools の verify/bundle は同じ規則で自動配信する):

```bash
# 例: デッキが ~/work/presentations/foo/、スキルが ~/.claude/skills/webdeck/ なら共通祖先は ~
cd <共通祖先> && python3 -m http.server 8000
# → http://localhost:8000/<共通祖先からデッキへの相対パス>/ を開く
```

`index.html` をダブルクリック(file://)でも動くように作られているが、
ブラウザ差異を避けるため発表本番前の確認はサーバ経由で行うこと。
配布相手にダブルクリックで開かせたい場合は単一 HTML(§5)を渡す。

## 2. 2画面での発表手順(プロジェクタ+手元)

1. ブラウザでデッキを開き、**S** キーでスピーカービューを開く
   (タイマー/現在・次スライドのプレビュー/スピーカーノートが出る別ウィンドウ)。
2. スピーカービューのウィンドウを**手元の画面**に移動する。
3. メインウィンドウを**プロジェクタ側**に置き、**F** で全画面にする。
   **スピーカービューを開くと、聴衆側画面の操作ドックは自動的に消える。**
4. 以後の進行は**スピーカーウィンドウ左下の操作バー**から行える:

   さらに、**ウィンドウ左側に全スライドのサムネイルレール**が常時表示される
   (PowerPoint の通常画面の左ペインと同じ)。現在のスライドがハイライトされ
   常に中央へ自動スクロール、クリックでそのスライドへ即ジャンプできる。
   サムネイル画像は、単一 HTML(`bundle.mjs`)では**バンドル時に自動生成して
   埋め込まれる**(+数百KB。省きたい場合は `node $PP/tools/bundle.mjs <deckDir> --no-thumbs`)。
   ソースから開く場合は `verify.mjs` のスクショが使われ、どちらも無い時は
   番号+タイトルのカードに自動フォールバックする。

   | 操作バー | 動作 |
   |---|---|
   | ◀ / ▶ + 番号 | 前後移動(fragment 含む)と現在位置 |
   | ≡(一覧) | 左のサムネイルレールの表示/格納 |
   | 🖵(モニター) | 聴衆画面の操作ドックの表示/非表示切替 |

   キーボードでも操作できる(スピーカーウィンドウにフォーカスがある状態で
   `→` `←` `Space` など — 本体側が動き、プレビューは自動追従する)。

   操作バーの位置はデッキの `PPShell.init` で変更できる:

   ```js
   PPShell.init({
     title: '…',
     speakerBar: 'bottom-left'  // bottom-right(既定) / bottom-left / bottom-center / top-left / top-right
   });
   ```

   なお、ウィンドウの縦横比が 16:9 でなくても(メイン・スピーカーウィンドウの
   プレビューとも)**スライドは背景アートまで含めて常に 16:9 のブロックとして
   固定描画**され、余白はレターボックス(テーマの `--pp-letterbox` 色)になる。
   ウィンドウをどう変形してもスライドの見た目は変わらない。

**ペーシング**: `PPShell.init` の config に `totalTime`(発表時間・秒)を渡すと、
スピーカービューのタイマーが進行ペースの目安を示す:

```js
PPShell.init({
  title: '…',
  config: { totalTime: 1200 }   // 20分
});
```

### 会議アプリへのウィンドウ共有(投影ウィンドウの切り出し)

Zoom / Teams などで「画面全体」ではなく 1 ウィンドウだけを共有したい、しかし
ブラウザの URL バーやブックマークバーは映したくない — という時は、ドックの
**投影ウィンドウボタン**(四角+斜め矢印のアイコン、スピーカービューの隣)を押す。
デッキが最小クロームのポップアップ(スピーカービューと同じ見た目のウィンドウ)で
もう 1 枚開き、ウィンドウタイトルに「— 投影」が付くので共有ピッカーで見分けられる。

1. ドックの投影ウィンドウボタンを押して切り出す —
   **元のウィンドウは自動でスピーカービューに切り替わる**(タイマー・ノート・
   サムネイルレール・操作バーが出る。別ウィンドウは増えない)
2. 会議アプリの画面共有で「— 投影」のウィンドウを選ぶ
3. そのままスピーカービュー(操作バーかキーボード)から進行する —
   投影ウィンドウが自動で追従する

- スピーカービューをやめて元のスライド表示に戻したい時は、**操作バー右端の
  戻るボタン**(ドア+矢印のアイコン)を押す。投影ウィンドウを閉じた時も
  自動でスライド表示に戻る。切り出しボタンをもう一度押せばスピーカービューに
  再切替できる
- **S** で先に別ウィンドウのスピーカービューを開いていた場合は、そのまま
  その別ウィンドウを使う(元のウィンドウは切り替わらない)
- 元ウィンドウと投影ウィンドウは**双方向で同期**する(スライド位置・fragment)。
  どちらを操作してももう一方が追従する
- **一覧(O)とスクロール閲覧は手元専用** — 一覧はタイルのオーバーレイとして
  手元だけに表示され、タイルをクリックした瞬間に両ウィンドウがそのスライドへ
  移動する。スクロール閲覧はモード中の移動が投影側に流れず、抜けた時に選んだ
  位置へ一度だけ追従する
- ボタンをもう一度押すと既存の投影ウィンドウにフォーカスする(2 枚は開かない)
- 投影ウィンドウ側にも操作ドックはある(マウスを動かすと数秒表示。開いた直後の
  自動表示はしない)。共有中に映るのが気になる場合は、投影ウィンドウ側で **D** を
  押して無効化しておく(もう一度で復帰)
- 動画・音声の再生状態は同期しないので、再生操作は投影ウィンドウ側で行う
- プロジェクタ直結の 2 画面発表(上記)では通常この機能は不要 — F の全画面で足りる

## 3. キー一覧とコントロールドック

| キー | 動作 |
|---|---|
| `→` / `Space` | 次へ(fragment を含む) |
| `←` | 前へ |
| `O` | スライド一覧の切替 |
| `G` | 番号入力でジャンプ |
| `F` | 全画面 |
| `S` | スピーカービューを開く |
| `D` | 操作ドックの表示オン/オフ(発表中に即座に消したい時) |
| `?` | ショートカット一覧 |
| `Esc` | 一覧・全画面・ジャンプ入力の解除 |

**コントロールドック**: マウスを動かすと画面下端中央に半透明のツールバーが現れる
(数秒で自動的に隠れる)。前後移動・スライド番号(クリックでジャンプ)・一覧・
スクロール閲覧・スピーカービュー・投影ウィンドウ切り出し・全画面・
ヘルプがワンクリックで使える。キーを覚えていなくてもドックだけで一通り操作できる。

**一覧(O)**は全スライドのサムネイルをタイル状のグリッドで俯瞰するオーバーレイ。
マウスホイールで上下にスクロールでき(スクロールバー付き)、クリックでその
スライドへジャンプ、**Esc / O / 余白クリック**で閉じる。サムネイルはスピーカー
ビューのレールと同じ仕組み(単一 HTML では埋め込み画像、リポジトリからは
verify のスクリーンショット、どちらも無ければ番号+タイトルのカード)。
単一 HTML(§5)ではさらに **PDF ダウンロード**ボタンが現れ、バンドル時に
埋め込まれた正式 PDF(`export-pdf` の検証済み成果物と同一)をその場で保存できる。
発表中に完全に消したいときは **`D` キー**(もう一度で復帰)。
**スピーカービューを開いている間は自動で消え**、出したい場合はスピーカーウィンドウの
モニターボタンから切り替えられる。
進行位置はページ番号(右下)とドックのカウンタで把握する(下端プログレスバー等のクローム表示はテーマが決める — 例: aws テーマはブランド準拠で非表示)。

## 4. URL パラメータ(閲覧モード)

- **`?view=scroll`** — 縦スクロールで全スライドを読めるモード。
  「発表は見られないので後で読みたい」人への共有リンクに向く。
  ドックの「スクロール閲覧」ボタンでも切替できる。
- **`?view=print`** — 印刷ビュー。全スライドを縦に並べ、ブラウザの印刷
  (PDF に保存)にかけられる状態にする。通常は §5 の `export-pdf.mjs` を
  使えばよく、手動で開く必要はない。

## 5. 配布の4形態

すべて成果物は `<deckDir>/out/` に生成される(パスはコマンド出力に表示)。
**フル版と配布版は別物** — スピーカーノートは登壇者向けの内容(進行メモ・補足)を含むため、
聴衆・顧客へ渡すのはノート削除版にする。ノートに内部メモや作業用語を書かない規律も前提
([CONTENT.md](CONTENT.md))。

| 形態 | コマンド | 用途・特性 |
|---|---|---|
| 単一 HTML(フル版) | `node $PP/tools/bundle.mjs <deckDir>` | 1ファイルにすべて埋め込み。ダブルクリックで開け、スピーカービューも動く。配布用 PDF も自動生成して埋め込まれ、**ドックの PDF ボタンで受け手がその場でダウンロードできる**(サイズは +PDF の約1.3倍(base64)。省くには `--no-pdf`)。**スピーカーノート入り — 登壇者本人にだけ渡す** |
| 単一 HTML(配布版) | `node $PP/tools/bundle.mjs <deckDir> --strip-notes --dist-title "<配布ファイル名>"` | `aside.notes` を**完全削除**した聴衆・顧客向け。生成時に aside が 0 個であること・スライド数が不変であることを自動検証する。`--dist-title` は出力名と埋め込み PDF のダウンロード名(既定はディレクトリ名なので、日本語タイトル等へ差し替える) |
| PDF | `node $PP/tools/export-pdf.mjs <deckDir>` | 印刷・添付向け。fragment は1ページに畳まれる。ページ数の自動検証付き。フッター等の家具の見え方はテーマの規約に依存する(例: aws テーマはフッターを全ページ標準[小ロゴ+©]で統一し、タイトル系スライドのページ番号は画面表示と同様に非表示) |
| PPTX | `node $PP/tools/export-pptx.mjs <deckDir>` | PowerPoint 提出が必須の場合のみ。**各スライドを画像として貼る方式**なので見た目は完全一致だが、**先方で編集はできない**(ノートはテキストで入る。編集不可の注意書きはツールが出力する) |
| PPTX(直せる形) | `node $PP/tools/export-pptx-editable.mjs <deckDir> [--ea-font=Yu Gothic] [--font-map=元=先]` | 先方が PowerPoint で直す前提のとき。文字はテキストボックス、背景・枠線は図形、画像と SVG は画像。位置はほぼ合うが、折り返しの位置・グラデーション・影は近似になる。書体は Amazon Ember Display を Amazon Ember に、日本語は Yu Gothic にする(変えられる) |

## 6. トラブルシュート

- **S を押してもスピーカービューが開かない / 投影ウィンドウが開かない** —
  ブラウザのポップアップブロック。アドレスバーの通知から当該サイト(localhost 等)の
  ポップアップを許可してもう一度押す。
- **フォントが出ない/一瞬素のフォントになる** — 古いキャッシュを掴んでいる
  ことが多い。スーパーリロード(Ctrl+Shift+R / Cmd+Shift+R)。file:// で
  開いている場合はサーバ経由(§1)で確認する。tools のサーバは
  `Cache-Control: no-store` 配信なので verify/export ではこの問題は起きない。
- **動画が自動再生されない** — ブラウザの自動再生ポリシーによるブロック。
  音声付き動画は自動再生されないことがあるため、`muted` を付けるか、
  クリックで再生する運用にする。発表前に本番ブラウザで一度再生確認しておく。
