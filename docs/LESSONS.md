# LESSONS.md — 制作で得た学びの蓄積

このファイルはスキルの「学習帳」。**次のデッキでも通用する一般則だけ**を書く
(そのデッキ限りの修正は書かない)。

内容規範の既定値(ワーディング・レイアウト・図解・構成)は
[CONTENT.md](CONTENT.md) が正典。ここには「まだ正典に昇格していない、
セッション由来の学び」と「依頼者固有の規範への入口」だけを置く。

---

## 運用の原則

1. **二層で持つ**: 依頼者とのやり取りの逐語記録(FB対訳ログ)は**デッキ側プロジェクトに置く**
   (依頼者の文脈・固有情報を含むため、スキルには持ち込まない)。このファイルに書くのは、
   そこから**固有情報を落として一般化した学び**だけ。
2. **対訳型で記録する**: 「こちらの提示 → 依頼者の修正 → 一般則」の3点セットが1単位。
   指摘だけでなく**肯定評価(「これは良い・維持」)も同じ精度で記録する** —
   何を維持すべきかが分からないと、次の改善が良い箇所を壊す。
3. **再来したら昇格させる**: 同種の学びが2回出たら、それは規範化不足のシグナル。
   ①正典ドキュメント(CONTENT / ANIMATION / VIDEO / VERIFICATION / AUTHORING)への明文化
   ②機械ゲート(verify の検査軸)への実装、の転写を提案する。ここに置いたまま増やさない。
4. **セッション終了時に必ず提案する**: デッキ制作でフィードバックを受けたセッションの
   終わりに、一般化できる学びの追記文案をユーザーへ提示し、承認を得て記帳する。
   「提案しないまま終える」が最大の失敗モード(承認ゲートを書き込み禁止にしない)。

## デッキ側プロジェクトに置く FB 対訳ログの書式(テンプレート)

```
# FEEDBACK_LOG.md(デッキ側プロジェクトに置く)
## <日付> <一行要約>
- 提示: こちらが出したもの(逐語・スクショ参照)
- 修正: 依頼者の言葉(逐語。言い方の強度も情報 — 規範違反/適用漏れ/作り込み不足/保護指定)
- 一般則: 次回から従うこと(なぜそうするかを1行)
- 展開: 同族の箇所を全面スイープしたか・機械ゲート化したか
```
