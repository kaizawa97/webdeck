# VERIFICATION.md — 検証の正典

デッキの作り方は [AUTHORING.md](AUTHORING.md)、配布は [PRESENTING.md](PRESENTING.md)。
この文書は「**書いたものが本当に意図通りか、どうやって確かめるか**」だけを扱う。
SKILL.md の検証ループ節はここのダイジェストであり、判断に迷ったらこちらを正典とする。

書き方の方針: チェックリストの列挙ではなく **何を保証したいから何を測るのか** の順で書く。
検査は目的ではなく、保証したい性質の観測手段である。**性質を言えないチェックは削れる。
逆に、性質は言えているのに観測手段がないものが「盲点」であり、そこが事故になる。**

---

## 1. 原理 — 保証したい性質から観測手段を逆算する

デッキの品質は単一の軸ではない。デッキで起きうる欠陥を分類すると、保証したい性質は
次の 9 つに落ちる。検証ツールは各性質への観測手段として設計する。

| # | 保証したい性質 | 観測手段(何を測るか) |
|---|---|---|
| P1 | **出荷物が開いて壊れていない** | 配布実ファイルをヘッドレスで開き totalSlides / console error / 動画 readyState を実測 |
| P2 | **面が読める** | content-bearing テキストの**実効** px(SVG は viewBox スケール補正)/ コントラスト比 |
| P3 | **面の幾何が破綻していない** | はみ出し・非血縁要素の矩形交差・フッター帯とのクリアランス px・面の使用率(死に空間) |
| P4 | **意図した動きが意図通り動く** | 中間フレームの実測(方向・緩急・重なり)・終端フレームの整列 |
| P5 | **内容が正しい** | 出典の一次性・事実の裏取り・禁則語の静的 grep |
| P6 | **面と面が繋がっている** | 遷移の入出でバトン語の実文言一致・ノート内の参照(約束)の解決性 |
| P7 | **変えてはいけないものが変わっていない** | 終端 PNG の md5 一致・継ぎ目の RMSE・尺の不変 |
| P8 | **配布するすべての形態で P1〜P7 が成立** | ソース / 単一 HTML / PDF / PPTX / ノート削除版それぞれに対する実測 |
| P9 | **検証の証跡が出荷物を指している** | report の生成時刻 > ソース mtime・PNG 枚数一致・配布先コピーの byte 一致 |

`verify.mjs` が既定で覆うのは P1・P2・P3 と、静的アサートによる P5・P8 の一部である。
**P4・P6・P7 には専用のコマンドか人の目が必要**で、P9 は report を読む側の規律である。
運用で検証ツールを足し続けることになる原因は、たいてい規範の不足ではない。
**足りないのはルールではなく観測手段**である。

### 原理 1: 「機械ゲート PASS」は品質の主張ではなく、前提条件の主張である

verify が PASS と言えるのは「verify が見ている軸で問題がない」ことだけ。
一般化すると **lint は網であってレビュアーではない**。網は目より細かいものを通す。
そして網は「自分の目が粗いこと」を報告しない。だから機械ゲートは**必ず**他の層と併走させる。

### 原理 2: 症状の場所と原因の場所はずれる

素朴な QA を素通りする欠陥は、ほぼ全部このクラスである。

- アニメの毎フレーム更新が存在しない要素を参照して例外を投げ、**無関係な後続要素**が動かない
- 統合ツールが `<style>` だけを巻き上げ、**編集していない別の面**が崩れる
- 面数が減って旧番号のスクショが残り、**独立評価者の所見**が残骸由来で汚染される
- ラベル座標を右へ動かした変更が、数ラウンド後に**別要素との重なり**として顕在化する

したがって「変更した箇所を確認する」では足りない。対策は 2 方向ある。
**変更したものと同じ性質を持つ集合全体をスイープする**(§3 の横展開スイープ)ことと、
**変更していないはずのものが変わっていないことを証明する**(§4 の md5 / RMSE)ことである。

## 2. 三層検証モデル — 機械ゲート / 自分の目 / 独立監査

一つの層で全部を捕まえようとすると必ず漏れる。3 層は**捕まえる欠陥のクラスが違う**。

### 層 1: 機械ゲート(verify・静的アサート・probe)

- **強み**: 反証可能・安価・反復可能・全枚に等しく適用される。数値で言える。
- **捕まえる**: 定義済みの軸の逸脱(はみ出し px・コントラスト比・禁則語・タグ均衡・実効フォント px)。
- **原理的に捕まえられない 4 種**:
  1. **定義していない軸**の欠陥(フォント床を実装していなければフォント床は永久に通る)
  2. **終端静止面以外**の状態(verify は fragment 全表示・`animations: 'disabled'` で撮る)
  3. **「違和感」**(重なっていないが詰まりすぎ・意味不明な図・変な位置の改行)
  4. **自分の盲点**(誤検知は報告するが、見ていない領域があることは報告しない)
- **運用規律**: ゲートは exit code で落ちること。警告止まりの軸は事実上ゲートではないので、
  警告に置くなら「誰がいつ目で見るか」を決める。出荷前は `--strict` で警告を FAIL に昇格させる。

### 層 2: 自分の目(作った本人の目視)

- **強み**: 違和感を検出できる唯一の安価な層。スクショを 1 枚ずつ開くだけ。
- **捕まえる**: 不自然な改行・要素の重なり・背景と文字の被り・文字化け・詰まりすぎ・死に空間。
- **弱み(構造的)**: **作者バイアス**。作者は意図を知っているので、意図が読めない図でも読める。
  内部レビューを何周回しても依頼者の指摘する欠陥が残存するのはこれが原因である。
- **運用規律**: 「レポート指摘ゼロ」は目視をスキップする理由にならない。逆で、
  **指摘ゼロのときこそ目視する**(指摘があるときは直すので、どうせ見る)。
  重点的に見るのは、機械ゲートが原理的に見ていないもの(report の「見なかったもの」欄)。

### 層 3: 独立監査(作った本人以外・読み取り専用・閾値付き)

- **強み**: 作者バイアスがない。意図を知らないので「伝わるか」を実際に試せる。
- **捕まえる**: 意図と実物のズレ・他面との矛盾・聴衆視点の欠落・規範の不適用。
- **設計上の必須条件**:
  - **読み取り専用**。監査者はデッキに書き込まない(所見ファイルへの append のみ)。
    書き込ませると「作った本人」に退化して層 3 の意味が消える。
  - **閾値を宣言する**。「聴衆が『あれ?』と思うレベルのみ report」のように書く。
    閾値がないと既知・許容済みの軽微指摘を再収集して空回りする。
    **周回ごとに足切りを上げる**。前周で直した領域は差分監査に切り替える。
  - **章ごとにディスクへ append**。数十枚を通読する監査者はコンテキストが尽きる。
    所見が 1 章ずつ残っていれば、途中で落ちても後継が引き継げる。
  - **良い点も 1 行書かせる**。指摘だけ求めると、成立している設計判断まで
    「改善余地」に見えてくる。抑制した判断(あえて情報を足さなかった等)を
    正しく評価できるかは、監査者の信頼度そのものである。
- **弱み**: 高コスト。だから対象を絞る(新設面・変更面・最重要面)。

### 層 3.5: 完全性クリティック(「検証済み」という主張自体を攻撃する)

3 層を全部回しても、**「回した」という記録が出荷物を指していない**ことがある。
この層が読むのは**出荷物ではなく証跡**である。手法は、依頼者の要求の全文 × 検証証跡 ×
出荷物の実測を突き合わせ、「記録に証跡がない出荷面」「要求と実物の矛盾」を探す。
発見の型は 4 つに定型化できるので、そのままチェックリストになる。

1. **規範のスコープ漏れ** — その規範は出荷集合の全部に適用されたか
   (後から足した面・付録的な面・配布派生も含めて)
2. **証跡の鮮度失効** — report の生成時刻は出荷物の最終改変時刻より後か
3. **証跡の非再現性** — 「PASS した」の根拠が本文の言明でなく、成果物として残っているか
4. **レンズのスコープ漏れ** — 各監査が明示した対象集合と、出荷集合の差分は何か

**運用規律**: この層には「誤報回避のため確認済みリスト」を必ず書かせる。
「この疑いは実測で否定した」を明記させると、リードが指摘を額面で受け取れる。
攻撃的な監査は、外した攻撃も申告させて初めて使える。

## 3. 監査レンズのカタログ

レンズは「**どの性質を・どの集合に対して・どう測るか**」の三つ組で定義する。
以下は、素朴な QA を素通りしやすい欠陥のクラスごとに定義したレンズである。

### レンズ 1: 新設面専用監査

- **性質**: 新しく足した面が、既に監査で確立した品質水準に乗っていること(P2・P3・P5)。
- **原理**: **新設面は過去の監査を継承しない。** 「監査済み」の状態は、そのとき存在した面に
  しか適用されていない。新設面は機械ゲートは通るが、文言規範・ヘッジ表現・レイアウトの
  根治はどれも自動では乗らない。
- **手法**: 面を新設/統合したら、その面だけを対象に独立監査を 1 回通す。
  視点は 3 つ(視覚品質 / 既存本編との整合と出典の逐語一致 / その面の用途)。
- **典型的な欠陥の型**: ヘッジ済みの断定表現が無ヘッジ形で再導入される・開示済みの出典条件を
  誤分類して内部矛盾になる・根治済みのレイアウトバグの同族が再発する・空帯(死に空間)が残る。
- **一般則**: 既存の修正履歴と**同じ主題を扱う**新設面は、**修正済みの表現をコピー元にする**。
  無印の初稿や古いドラフトからコピーすると、直したはずの欠陥が復活する。
- **発動条件**: 面の新設・統合・大幅な作り直しのたび。必須。

### レンズ 2: 参照/約束グラフ監査

- **性質**: 面やノートの中で行った「約束」が実際に履行されていること(P6)。
  登壇者がノートを信じて動いて裏切られないこと。
- **手法**: 全面のノート・本文から「参照」と「予告」を全部抽出し、1 件ずつ
  **ターゲットの存在**と**ターゲットが実際に約束を果たしているか**を検証する。
  「後半で 4 段階として示す」なら、その面に 4 段階のモデルが本当にあるかまで見る。
- **典型的な欠陥の型**: 内容の欠落はまず出ない。出るのは全部**ポインタのドリフト**である
  (off-by-one・折り畳みで消えた面への参照・同一章の次面を「次章」と呼ぶ章ラベル誤り)。
- **一般則**: **内部 ID(連番・内部コメントの面 ID)による参照はドリフトする。**
  面の増減・折り畳み・並べ替えのたびに全参照が腐る。参照は **content 名 / 章ラベル
  (aws テーマでは eyebrow)** で書く。これは恒久対策であって、番号を直し続けるのは対策ではない。
- **同居させると安いもの**: 章ラベル(eyebrow 等)の連番性・アジェンダとディバイダの文言一致・
  section と aside の 1:1 対応。
- **発動条件**: ノート・参照を編集したラウンドの終わり。面の増減があったら必須。

### レンズ 3: 遷移監査

- **性質**: 面が個々に正しいだけでなく、**面と面の間**で語りが断絶・矛盾・重複していないこと(P6)。
- **原理**: 機械ゲートも面単位の目視も、**面の境界を誰も見ていない**。1 枚ずつ直すと境界が壊れる。
- **手法**: 変更した面の **入(前面→当面)と出(当面→次面)** を 1 本ずつ審査する。
  判定は印象ではなく**バトン語の実文言一致**で裏取りする(前面ノートの結び語が
  次面の冒頭語と一致しているか)。閾値は高く取る(断絶・矛盾・重複のみ報告)。
- **模範となる継ぎ目の型**: バトン語の完全一致 / 直接コールバック(「先ほどの例が示すとおり」)/
  予告→実演(「次に詳しく見ていく」→ アニメ)。
- **副産物**: 報告閾値未満の watch リスト(トーン落差・意図的な繰り返し・出典差)を残す。
  「見たが報告しない」の明示であり、次周の監査者が同じものを再収集するのを防ぐ。
- **発動条件**: 内容・語順・面の位置を変えたラウンドの終わり。

### レンズ 4: 出荷実物のフレーム QA

- **性質**: 動く要素が、**出荷された実ファイル**の中で意図通り動いていること(P4・P1)。
- **原理**: 動画スライドの検証 PNG は信用できない。verify は poster か、ヘッドレスの
  メディアキャッシュに残った**差し替え前のフレーム**を写す。
  「終端は正常なのに再生の途中だけ壊れる」バグは静止 QA を原理的に素通りする。
- **手法**: **出荷 mp4 から ffmpeg で直接フレーム抽出**し、疑わしい箇所を拡大クロップして見る
  (`ffmpeg -ss <t> -vf "crop=W:H:X:Y,scale=..."`)。修正前後を同一タイムスタンプで並べて証跡化する。
  in-slide アニメは `anim-qa.mjs` の中間フレームで同じことをやる。
- **重要な運用**: **全数やる。** 欠陥が 1 本にしかなくても、どの 1 本かは事前に予測できない
  (依頼者が名指しした面だけを見ても、名指しされていない面の欠陥は捕まらない)。
- **発動条件**: 動画/アニメを含む面の出荷前。座標・レイアウトを触ったら再実行。

### レンズ 5: 完全性クリティック

§2 の層 3.5 に詳述。**出荷物ではなく証跡を読む**唯一のレンズ。
「全層検証済み」という主張・要求の全文・出荷物の実測を三つ巴で突き合わせ、
4 型(規範のスコープ漏れ / 鮮度失効 / 非再現性 / レンズのスコープ漏れ)を機械的に当てる。

### レンズ 6: 横展開スイープ(方向整合スイープ)

- **性質**: 一箇所で見つけた違和感が、**同型の性質を持つ全要素で根絶**されていること。
- **原理**: 修正の完了報告は「直した」であって「根絶した」ではない。
  **依頼者が 1 箇所を指摘したときは、それは代表例である。**
- **手法**: 指摘された欠陥の**性質を抽象化**し(例:「回転方向が参照要素と矛盾する」)、
  出荷全面からその性質を持つ要素を棚卸しして 1 個ずつ判定する。
  判定の内訳(正・矛盾参照なし・未使用の孤児 CSS 等)まで書くと「網羅した」が言える。
- **レンズの粒度について**: 面単位で PASS を出すと、**面の中の未検査要素が PASS に含まれる**。
  高倍率で精査した回転要素の隣に、見ていない別の回転要素が残りうる。
  → **レンズの粒度は「面」ではなく「性質を持つ要素」で切る。**
- **発動条件**: 依頼者の指摘を修正した後、必ず。「1 箇所直した」で閉じない。

### レンズ 7: ゼロコンテキスト聴衆シミュレーション

- **性質**: 前提知識のない聴衆に、意図した内容が意図した順で伝わること。
- **手法**: ゼロコンテキストのペルソナに全枚のスクショを通読させ、所見を採る。
- **既知の運用上の罠**(潰さないとレンズが誤った所見を返す): 残骸 PNG による汚染・
  コンテキスト死・構造化出力の JSON 破損。いずれも §6 の C 群で対処する。
- **発動条件**: 内容が固まったあと・出荷前。周回ごとに閾値を上げる。

### レンズ 8: 静的コンテンツ lint

- **性質**: 文言規範のうち**機械判定可能な部分**を全面で漏れなく守ること(P5)。
- **手法**: ブラウザ不要・HTML を直接パース。RED は exit 1 でゲートにする。
  軸の例: 依頼者本人の資料に由来する出典表記・自己言及ラベル・
  見出し内の句読点・デッキごとの禁止語。誤検知回避のため除外領域を明示する。
- **設計上の要点**: **RED と WARN を分ける。** 「一次出典でない可能性が高い」のような
  判定不能なものを RED にすると、ゲート自体が信用されなくなる。WARN は人が見る。
- **限界の自覚**: lint は**規範の一部**しか表現できない。
  機械的な判別に寄りかかると、規範に触れない種類の違和感を見逃す。

### レンズ 9: 配布同値性スモーク

- **性質**: **出荷する実ファイル**が、正典と同じ内容・同じ挙動を持つこと(P8)。
- **原理**: 正典 bundle のスモークは、配布派生が生成される**前**に走る。
  派生の生成器が静的アサートしか持たないなら、配布実物は一度も実行されていない。
- **手法**: 配布先に置く実ファイルをヘッドレスで開き、totalSlides / aside DOM 数 0 /
  禁止語 0 / 動画の readyState と再生 / フォント床のライブ実測 / 最終面のラベルを測って
  **JSON として永続化**する。
- **一般則**: 「配布版検証済み」は、**配布実ファイルに紐づいた再現可能な成果物**がある時だけ言える。

### 指摘ゼロだったレンズについて

指摘ゼロは無駄ではない。**「壊れていないことの証明」**である。
「アニメを追加したが第三者が違和感を持たなかった」は、追加した演出が意図通りである
ことの独立確認として記録する価値がある。ただし空振りが続いたら
**閾値を上げるのではなく、レンズを変える**。粒度を変えると、前周が PASS を出した面から欠陥が出る。

## 4. 証明の様式 — 「大丈夫です」の代わりに何を出すか

最も効く規律は、**主張を測定値に変換する**ことである。「重なっていません」「方向を直しました」
「静止面は変わっていません」は、どれも実測値に置き換えられる。置き換えると
(a) レビュアーが再検証できる (b) 次回の回帰検出のベースラインになる
(c) 報告と実体の乖離が起きなくなる。

### 4-1. 終端 PNG の md5 一致 — 「静止面は 1 画素も変わっていない」

アニメを追加/変更したが、最終型(= PDF・PPTX・verify PNG に焼かれる面)は不変であることの
証明(P7)。`verify.mjs --baseline <変更前デッキのコピー>` が 1 コマンドでやる。手作業で組むなら
**両方を同じ serve root(共通祖先)から配信**し(デッキ内の相対参照を解決させるため。root が
ずれると資産が 404 になって「差分あり」の誤判定になる)、reduced-motion 相当 +
`animations: 'disabled'` で撮る。この様式の強みは **DOM を組み替えた面でも画素同一を示せる**点で、
実装の自由度を保ったまま不変を保証できる。

### 4-2. RMSE 画素比較 — 「継ぎ目が繋がっている」

連続再生する 2 本の動画で、**前の終端フレーム**と**次の frame0** が一致していること。分割した
アニメは、この一致が崩れると視聴者に「飛び」として見える。各継ぎ目に恒久 ID(J1・J2…)を振り、
ラウンドごとに RMSE を記録して比較する。**0 でなくてもよい — 前ラウンドから動いていないことが
要件**である。併走する規律が 2 つ: 継ぎ目は**特定のアンカー**(点の位置・ヘッダ)で判定する
(**中間だけを延長すれば frame0 と終端は不変**なので、尺を伸ばしても継ぎ目は PASS のまま保てる)。
frame0 の複製には前半終端で**見えている全要素**を入れる(うっすらした補助線を落としただけでも
継ぎ目差分は大きく出る)。

### 4-3. 座標時系列 — 「方向が正しい」

回転・周回・掃引の**向き**の証明。目視の「反時計回りに見える」は主観で、それだけでは要素を
見逃す。動く要素(ダッシュの重心など)の座標を複数時刻でサンプリングし、
中心からの math 角度が**単調増加(CCW)/単調減少(CW)** であることを示す。出荷 mp4 の
フレーム 3 枚で「12 時 → 10 時 → 8 時」を独立確認すると補強になる。
**「向き」「順序」「増減」のような時間に沿った性質は 1 フレームでは証明できない** —
必ず 3 点以上のサンプルを並べる。

### 4-4. gap px — 「重なっていない・クリアランスがある」

**用途**: 重なりの不在は「重なっていません」ではなく **gap の実数値**で言う(P3)。
矩形交差は面積で言う(検出閾値の例: 面積 > 4)。`verify.mjs` の重なりスイープが全面分を出す。

**測定の設計要点 4 つ**:

1. **枠線・背景を持つ箱も対象にする**。テキストの子要素は帯の上で止まっているのに、
   親の箱の**境界線がフッターに食い込む**実害がある。テキストだけ見ると取りこぼす。
2. **全画面ラッパを除外する**(高さ > 0.9×canvasH または幅 > 0.99×canvasW)。
   除外しないと section 自身が常にフッターと交差して誤検知になる。
3. **血縁(`contains`)を除外する**。親子の交差は当然なので、非血縁のペアだけを見る。
4. **fragment を全部強制表示してから測る**。opacity で隠れているだけの要素も最終レイアウトに参加する。

同じ実測の応用として、棒や円の実寸を注記した倍率と突き合わせれば
「同一軸上で規模が一貫している = 対比を誇張していない」という**誠実性**も数値で言える。

### 4-5. 実効 px — 「投影して読める」

**用途**: フォント床の判定(P2)。**SVG `<text>` は属性の font-size と実際の見た目が一致しない。**
viewBox でスケールされるので、`font-size="16"` でも 9px に縮小レンダされていることがある。

**実効 px = font-size × (実描画幅 / viewBox 幅)**。HTML テキストは computed font-size が
そのまま実効 px になる(Reveal の transform が none の前提)。`verify.mjs --font-floor=<px>` が
両方を換算して全数列挙する。判定対象は content-bearing で、出典・キャプションと、
テーマ契約が宣言する小型役物(`template.json` の `verify.fontFloorExclude`。
aws テーマの宣言例: `.eyebrow`)は除外。

**拡大したら overflow が出る**のは正常な副作用で、そこは line-height と padding の圧縮で吸収する。
font-size を戻すのは禁止 — 規範が要求しているのは font-size そのものである。

### 4-6. 実時間サンプリングと getComputedTiming — 「緩急が意図通り」

**用途**: アニメのテンポの証明。「速すぎる/遅すぎる」は典型的なフィードバック軸である。

**二段構え**で安く回す。まず 1 面で**実時間の opacity サンプリング**をやり、CSS の delay が
実時間に忠実であることを実証する(例: 700ms 間隔の stagger なら opacity>0.5 到達がほぼ等間隔で並ぶ)。
以降の面は **getComputedTiming の delay 値 + currentTime スクラブの順序確認**で代替する。

**注意**: `transform` で stagger している要素は opacity サンプリングでは測れない
(全部同じ時刻に見える)。この場合は delay 値とスクラブで確定する。
「間隔 160/160/280/320/380ms = 前半速く後半だんだん溜める」のように書ければ、
緩急の要求充足を数値で言える。

### 4-7. 鮮度 3 式 — 「この証跡は出荷物のものである」

どれも安いが、どれも破れると**すべての PASS が無効になる**(P9)。

1. `report.generatedAt` **>** デッキソースの最新 mtime(最終編集より後に検証したか)。
   `verify.mjs` は両方を report.json に記録するので、**リードは毎回この不等式を見る**
2. `report.slideCount` **==** 実在する `slide-*.png` の枚数(残骸/欠落の検知)
3. 配布先コピーの **byte 一致**(同期漏れの検知)

### 4-8. 証跡の永続化と 2 系統の独立一致

- **永続化**: 「実行して PASS だった」ではなく、**JSON / MD として残った成果物**にする。
- **2 系統の独立一致**: 静止描画が不変な変更(自動送り・ランタイム挙動)は PNG では判定できない。
  この場合は**実装者と統合者が独立に実操作検証して一致すること** + reduced-motion / print の
  早期 return + スライド PNG 差分 0 枚、の組み合わせで判定する。
- **報告と実体の乖離を潰す**: 受領報告を鵜呑みにせず、**grep / 実測で反映を確認してから次のゲートへ**。
  編集した本人の「直しました」は証跡ではない。

## 5. 生成時の 4 段ゲート — 初版を最終品質にする

運用で見つかる欠陥のほとんどは、**生成の瞬間に測ればその場で防げた**ものである。
発見済みの欠陥クラスを生成時のゲートに落とせば、初版の品質が最終品質に近づく。
ゲートは**発火するタイミング**で 4 段に分ける。早い段で捕まえるほど修正が安い。

### 段 1: 執筆時の不変条件(コードを書く手が守る)

機械では測りにくいが、規約として先に宣言しておけばコストゼロで守れるもの。

- **実データは初期 HTML に確定値で書く**([AUTHORING.md](AUTHORING.md))。スクショ・PDF・PPTX は
  アニメ無効で描画されるので、JS で後入れした値は配布物に誤値で焼かれる
- **アニメは「終端 = 完成形」に設計する**。終端が完成形なら PDF・verify PNG・PPTX が自動的に
  不変になり、静止面の再監査が不要になる。終端が途中状態のアニメは、配布形態すべてに監査コストを生む
- **参照は内部 ID でなく content 名 / 章ラベル(eyebrow 等)で書く**(レンズ 2)。番号は必ずドリフトする
- **方向を持つ演出は、同じ面の他の方向要素と揃えてから書く**(レンズ 6)。
  特に **SVG の `circle` は固有のパス方向が時計回り**なので、dashoffset を素直に流すと CW になる
- **回転・拡大の原点は `transform-box: fill-box`(bbox 相対)で指定する**。px 値の
  transform-origin は SVG ユーザー座標系で解釈されて中心がずれる。ただし
  **線のドロー(scaleX)は `view-box` 原点**を使う — 零高 bbox では fill-box が不安定になる
- **アニメの毎フレーム更新は存在しない要素を参照しない**。1 個の null 参照が例外を投げると、
  それ以降の更新が丸ごと脱落して**無関係な後続要素**が動かなくなる

### 段 2: 面を書き終えた直後(per-slide ゲート)

1 面ごとに、その面だけを対象に測る。全枚まとめてやると原因の切り分けが遅くなる。

| 測るもの | 何を保証するか | 判定 |
|---|---|---|
| **実効フォント px 床** | 投影して読める(P2) | content-bearing の実効 px ≥ 床値(読ませる数字/ラベルは +2 以上)。SVG は viewBox 補正 |
| **フッター/ロゴのクリアランス** | 帯と content が衝突しない(P3) | 帯の矩形と content 葉要素の交差面積 = 0。gap px を記録。**枠線・背景を持つ箱も対象** |
| **非血縁要素の矩形交差** | 要素同士が重ならない(P3) | 交差面積 > 閾値 = 指摘。fragment を全表示にしてから測る |
| **キャンバスはみ出し** | 面が切れない(P3) | `overflow: hidden` の祖先で測定矩形をクランプする(§6 の A-1) |
| **死に空間(面の使用率)** | 余白を残さない | 空帯の高さと位置を測る。数値で出して圧縮する |
| **見出し 1 行・禁則** | 変な位置で改行しない/句読点なし(P5) | h2 の実描画行数 = 1、h2 内に句点・読点が無い |
| **コントラスト** | 読める(P2) | SVG は `fill` を前景色として解決。判定不能は skip 件数として表示 |

### 段 3: デッキを組み終えた直後(deck ゲート)

面単位では見えない、面の集合としての整合性。

| 測るもの | 何を保証するか | note |
|---|---|---|
| **`<aside>` の開閉均衡** | ノート削除派生が壊れない(P8) | 閉じタグ欠落は**スクショ検査を素通りする**。`grep -c` で開/閉一致を確認 |
| **section と aside の 1:1** | 全面にノートがある | 差分が出たら追加漏れか二重付与 |
| **章ラベル(eyebrow 等)の連番性** | 章内で欠番・重複・接尾辞のドリフトがない | **重複チェックだけでは欠番を見逃す**。章ごとに連続性を前版と比較する |
| **fragment ↔ 正典の diff = 0** | 再 splice で退行しない | `fragment.mjs` の check / resync で守る(下記) |
| **参照/約束の解決性** | ノートが嘘をつかない(P6) | レンズ 2 |
| **静的コンテンツ lint** | 文言規範の機械判定可能部分(P5) | レンズ 8 |
| **時間配分の合計** | 尺の制約 | 横断挿入は**統合者が配分表を中央設計 → 各担当は転記のみ**(分散させると合計が合わない) |

**分業デッキの fragment 同期について**: 複数の担当が章ごとの fragment を持ち、統合ツールが
正典 HTML に差し込む構成だと、独立した事故源が 3 つある。`fragment.mjs` の check / resync を
ペアで回して守る。

1. 統合が**整数 ID のみ置換**する一方 `<style>` は巻き上げるため、非整数 ID の面は
   本文が置換されないまま CSS だけ変わって崩れる
2. **古い fragment の CSS が正典を退行させる**(直接編集後に resync していないと、
   次の統合で古い定義が復活する)
3. 面の HTML を再 splice したのに **fragment の `<style>` マーカーを再置換していない**ため、
   新しい CSS クラスが未定義のまま overflow になる

### 段 4: 出荷直前(ship ゲート)— 配布形態それぞれの実測

**原理**: 「ソースで PASS」は「配布物で PASS」を意味しない。派生のたびに検査が要る。

| 形態 | 測るもの |
|---|---|
| **単一 HTML** | 全枚数・console error 0・スクショ notBlank・埋込 PDF の存在 |
| **ノート削除版** | 実ファイルをヘッドレスで開く: totalSlides・**aside DOM 数 = 0**・禁止語 0・動画の readyState と再生・フォント床のライブ実測。**JSON で永続化**(レンズ 9) |
| **PDF** | ページ数 = 面数。**動画面のポスターフレームが主張を伝えているか**。画面演出専用の装飾層(ぼかしゴースト・進行インジケータ)が静止面に焼き付いていないか(→ print 専用 CSS で演出層を非表示にする) |
| **PPTX** | 各面が画像として意図通り貼られているか・ノートがテキストで入っているか |
| **配布先コピー** | byte 一致(md5)。**新しいバイトが実際に内包されているか**も測る(動画を差し替えたら該当バイトを確認) |

**配布物の外周も統制対象**: 可視面だけでなく、HTML コメント・aria 属性・ノート・
**ダウンロードファイル名・bundle のソース**まで統制語を grep で掃く。bundle はソース閲覧可能である。

### ゲートの設計原則

- **ゲートは exit code で落ちること。** 警告止まりの軸は運用上ゲートではない。
  判定不能ケースがある軸は WARN に置き、**誰がいつ目で見るか**を決める(出荷前は `--strict`)。
- **RED / WARN を分ける。** 判定不能なものを RED にするとゲート自体が信用されなくなり、
  「またあの誤検知か」で本物の指摘が読み飛ばされる。
- **クリアランスは 0 でなく余裕込みで測る。** gap の実数値を出力すると、
  「今は当たっていないが 2px しかない」面が可視化されて次の事故を予防できる。
- **修正の副作用を必ず再測する。** フォントを拡大したら overflow が出る、
  ラベル座標を動かしたら別要素と当たる。**修正は新しい欠陥の生成イベント**である。

## 6. 誤検知・盲点リスト — 検証ツールが騙されるパターン

検証ツールの信頼性は、**誤検知(狼少年)と盲点(素通り)の両方**で壊れる。
**誤検知が多いと本物の指摘が読み飛ばされ、盲点があると PASS が意味を失う。**
以下はツールが騙される典型パターンである。各項に対処を付けた。

### A. 幾何測定が騙される

1. **CSS クロップのゴースト幾何** — `overflow: hidden` + 負マージンでのクロップは、`img` の
   raw box(クロップ前)が bbox に残ってはみ出しを誤検知する。→ 測定点を
   **`overflow: hidden` の祖先でクランプ**する。または事前クロップした派生アセットを使う(根治)。
2. **transform 由来の AABB 膨張** — 回転装飾は軸平行境界箱で測られ、見た目は内側でも
   はみ出しと出る。→ 警告に降格する(現行の設計は正しい)。ただし
   **降格したものを誰も見ないと盲点に変わる**ので、警告の目視担当を決める。
3. **表紙・クロージングのフッター配置が違う** — タイトル系レイアウトはフッター家具の配置が
   本文面と異なることがあり(aws テーマの例: ロゴが大型化して位置も変わる)、本文面と同じ
   帯判定をかけると全面誤検知になる。→ レイアウトクラスで判定を分岐する。帯高さ等の家具は
   テーマ契約(`template.json` の verify 節)が宣言し、verify はそれを読んで判定する。
4. **`.src` 脚注の bbox** — 出典行 `.src` は `position: absolute` の脚注で、帯まわりの配置が
   共通規約(`themes/README.md`)として仕様。→ 帯判定から除外する。ただし除外した結果、
   **箱の枠線・背景による本物の重なり**が別レンズ必須になる(§4-4 の要点 1)。
5. **全画面ラッパの交差** — section 自身や背景ラッパは常に帯と交差する。→ 高さ > 0.9×canvasH
   または幅 > 0.99×canvasW を除外する。
6. **血縁要素の交差** — 親子の矩形交差は当然。`contains` で除外しないとノイズだけになる。
7. **opacity で隠れた fragment も layout を占める** — 非表示の fragment span がキャプションの
   箱サイズに参加する。→ fragment 全表示状態で測る。
8. **probe が SVG に盲目** — 帯検査が SVG の height や `<text>` を数えない実装だと、
   SVG のみで構成された帯は素通りする。→ 走査対象に `svg` と `svg text` を含める。

### B. フォント・色の測定が騙される

9. **SVG の viewBox がフォントサイズを縮める** — 属性値だけ見ると床の判定が丸ごと嘘になる。
   → 必ず実効 px を計算する(§4-5)。
10. **コントラストが SVG の fill を読まない** — CSS の `color` を読むと SVG `<text>` は
    dark-on-dark の偽陽性になる(fill が明色なら実害なし)。→ SVG は `fill` を前景色として解決する。
11. **背景が判定不能なケースの扱い** — 背景画像・半透明背景の上のテキストは計算できないので skip する。
    → ただし **skip がレポートに見えないと盲点になる**。「判定不能 N 件・目視必須」として件数を出す。

### C. スクリーンショット / artifact が騙される

12. **残骸 PNG** — 面数が減ると旧番号の PNG が残り、独立評価者の所見を汚染する
    (「同じ面が 2 枚ある」「同じ語が連続する」といった所見は残骸の誤認でありうる)。
    → 実行前に `slide-*.png` を purge し、事後に **report.slideCount == PNG 枚数**を照合する。
13. **動画スライドの PNG が古い** — ヘッドレスのメディアキャッシュで差し替え前のフレームが写る。
    実体は正常でも PNG は旧内容。→ 動画面は PNG で判定せず、**mp4 から ffmpeg で直接抽出**する。
14. **終端は正常・中間だけ壊れる** — 静止 QA を原理的に素通りする最大の盲点。
    → アニメ面は `anim-qa.mjs` で中間フレームをサンプリングする。
15. **構造化出力の JSON 破損** — 監査エージェントに JSON を吐かせると未エスケープの引用符で壊れる。
    → 所見は MD で append させ、構造化は最後に一度だけ書かせる。
16. **screen の検査は print メディアに写らない** — verify のスクショは screen メディアで撮るため、
    print 専用スタイルの不良(例: PrintView が包み込み時点のレターボックス色を全ページに焼き付ける)は
    機械ゲートも目視パスも素通りする。→ **PDF は生成形式そのものをラスタライズして見る**。
    `export-pdf.mjs` は分散サンプルページの地色を自動検査する(過半数がレターボックス色なら FAIL)が、
    地色以外の print 不良は PDF の目視だけが防波堤。

### D. 運用・スコープが騙される

17. **面単位 PASS が面内の未検査要素を飲み込む** — → レンズの粒度を「性質を持つ要素」で切る。
    面 PASS を出すときは「この面の何を見て、何を見なかったか」を書かせる。
18. **監査スコープの明示が盲点を作る** — 「本編を対象」と正しく宣言した監査は、その宣言によって
    後から足した面を永久に対象外にする。→ スコープ宣言に必ず**出荷集合との差分**を併記させる。
19. **同じ閾値の反復で空回り** — 既知・許容済みの軽微指摘を再収集し続ける。
    → 周回ごとに足切りを上げ、修正済み領域は差分監査へ。
20. **番号系の二重ドリフト** — 指示や FB で使う「表示 N 枚目」と HTML の内部 ID コメントは
    別系統でドリフトする。番号で照合すると別の面を検証してしまう。→ 監査の最初に
    **content / 章ラベル(eyebrow 等)による実マッピングを作って報告に載せる**。指示の番号ゆらぎも明記する。
21. **タグ均衡がスクショ検査を素通りする** — 閉じタグ欠落はスクショでは見えず、
    配布派生の tag-assert のような静的アサートだけが捕捉できる。
    → 静的アサート(開/閉の数一致・派生前後の section 数不変)を deck ゲートに常設する。

### E. 症状の場所 ≠ 原因の場所(盲点として最重要)

22. **1 個の null 参照が下流の更新全体を落とす** — 毎フレーム例外で以降の更新が脱落し、
    **無関係な後続要素**が動かない/終端キャプションが出ない。
    → デバッグ規律: 症状の出た要素ではなく、**更新ループで最初に投げている例外**を疑う。
23. **座標変更の遠隔副作用** — ある要素を右へ動かした変更が、数ラウンド後に別要素との重なりとして
    顕在化しうる。→ 座標を触ったら重なりスイープを全面で再実行する。
24. **並行編集の静かな取りこぼし** — 沈黙したエージェントを死亡と即断して後継を起動すると、
    生きていた元エージェントとの二重書き込みで共有成果物が破損する。
    → **後継を立てる前に必ず旧オーナーを停止**し、単一オーナーを保証してから引き継ぐ。

## 7. ツールの使い方まとめ

`$PP` はスキル本体のディレクトリ。デッキと `$PP` の**共通祖先から自動配信**されるので、
デッキがどこにあっても `<deckDir>` を絶対パスで渡せば動く([PRESENTING.md](PRESENTING.md) §1)。

| コマンド / フラグ | 何をするか |
|---|---|
| `node $PP/tools/verify.mjs <deckDir>` | 全面のスクショ + 従来軸(はみ出し[`overflow: hidden` 祖先でクランプ]・console/HTTP エラー・フォント読込・コントラスト[SVG は `fill` を解決・判定不能は skip 件数を表示])+ 新軸(非血縁要素の重なりスイープ[フッター帯との gap px 一覧つき]・静的アサート[aside 開閉均衡 / section と aside の対応 / h2 内の句読点 / h2 の実描画 1 行])。**新軸は既定 WARN**。実行前に `out/verify/slide-*.png` を purge し、事後に report.slideCount == PNG 枚数を照合(不一致は FAIL)。report.json に生成時刻とデッキソース最新 mtime を記録 |
| `--strict` | 新軸の WARN を FAIL へ昇格(対象: 重なり交差・固定物交差・静的アサート[句読点+**自動折返し**])。明示的 `<br>` による複数行見出しは「意図確認」の注記に留まり昇格しない。gap 近接注意も昇格しない。**出荷前はこれで回す** |
| `--font-floor=<px>` | 実効フォント px 床の監査(HTML は computed、SVG は viewBox 補正)。対象は content-bearing(出典 `.src`・キャプションと、テーマ契約 `verify.fontFloorExclude` の宣言分[aws の例: `.eyebrow`]は既定除外、`--font-exclude` で調整)。**このフラグを付けたら床割れは FAIL** |
| `--baseline <dir>` | 変更前デッキとの静止面照合。**同一実行内で両デッキを同一条件・同一経路で撮り直して** md5 比較し(過去の PNG とは比較しない)、差分面と「比較不能(unstable = 同一デッキでも撮影ごとに変わる面)」を別枠で列挙する。結果は表示のみ(exit code に影響しない)。撮影結果は `out/verify/baseline/{current,before}/` に残り、差分面を並べて目視できる。「静止面不変」の証明が 1 コマンドになる |
| `node $PP/tools/anim-qa.mjs <deckDir> --slide <n> --times <秒,...>` | アニメ有効で中間フレーム PNG + コンタクトシートを出す。「終端は正常・途中だけ壊れる」への唯一の観測手段 |
| `node $PP/tools/bundle.mjs <deckDir> --strip-notes [--dist-title "<配布名>"]` | ノート完全削除の配布版を生成(aside DOM = 0 と section 数不変をスモークで検証)。`--dist-title` は埋込 PDF のダウンロード名 |
| `node $PP/tools/fragment.mjs check` / `… resync` | 分業デッキの fragment ↔ 正典の同期(段 3)。直接編集した面は resync してから次の統合に渡す |
| ffmpeg | **動画スライドの検証は verify PNG ではなく出荷 mp4 からのフレーム抽出**で行う(§6 の C-13) |

### 標準の検証シーケンス

**執筆中(面を書くたび)**:

```bash
node $PP/tools/verify.mjs <deckDir>          # 素で回す。WARN も読む
```

指摘を直したら、**スクショを 1 枚ずつ自分の目で開く**。
機械が原理的に見ていないもの(背景画像上のコントラスト・fragment の途中状態・
動画の中間フレーム)を重点的に見る。

**出荷前**:

```bash
node $PP/tools/verify.mjs <deckDir> --strict --font-floor=18
node $PP/tools/verify.mjs <deckDir> --baseline <変更前デッキのコピー>   # 静止面不変を主張するとき
node $PP/tools/anim-qa.mjs <deckDir> --slide <n> --times 0,0.5,1,2,3    # アニメ面ごと
```

1. **機械ゲート**を `--strict` で通す(+ フォント床)
2. **自分の目**で全枚見る。**指摘ゼロのときこそ見る**
3. **独立監査**を回す(新設面があれば専用監査は必須。読み取り専用・閾値宣言・章ごとに append)
4. **配布形態それぞれ**を実測し、証跡を成果物として残す(§5 の段 4)
5. **鮮度 3 式**を確認する(report の生成時刻 > ソース mtime・PNG 枚数一致・配布先 byte 一致)。
   ここまで揃って初めて「検証済み」と言える

### 最後に

依頼者の指摘への応答規律をもう一度書いておく。**指摘は代表例である。**
同じ性質を持つ要素を全面でスイープして初めて「根絶した」と言える(レンズ 6)。
そして **verify の PASS は品質の主張ではなく前提条件の主張**であり、
このループを通過するまで「完成」と言ってはならない。
