# CONTENT.md — 内容規範

`AUTHORING.md` が技術規約(壊れない書き方)を定めるのに対し、この文書は**内容の規範** —
何を書くか・どう見せるかを定める。ワーディング / レイアウト / ビジュアライズ / 構成の4領域。
デッキを書き始める前に AUTHORING.md と対で読む。各項は「なぜそうするか」を1文で持つ。

---

## 0. この文書は既定値であって、最上位の規範ではない

規範は、**依頼者の実物資料と、依頼者が模範として挙げた資料の分析から導出する**のが最優先。
良いスライドの条件はその組織・その聴衆・その場の文脈で決まるので、一般的な作法を既定に置いた
まま走ると、作法そのものが漂流の原因になる。

だから着手時に工程をひとつ持つ: 依頼者の過去資料・模範資料を入手し、ワーディング・情報密度・
構成の型を逐語で読み出して書き留める。**導出された依頼者固有の規範は、本文書の記述に優先する**。
本文書は、導出材料が無いとき、および導出結果が触れていない領域の既定値として働く。

## 1. ワーディング

- **面は聴衆への発話であり、広告コピーではない。** キャッチコピーの技法(体言止めの連発・対句・
  倒置・詠嘆・溜めの読点)は「感情を残して情報を落とす」ための技法で、資料の目的と正反対を
  向いている。解釈負荷をかけて内容量を減らすので、**一読で意味が確定する説明的な完全文**が
  常に優位に立つ。語順も倒置せず自然順に置く
- **タイトルに読点が要ると感じたら、それは構文が複雑すぎるという診断。** 見出しは主張の見出しで
  あって散文ではない。句点は「文が終止した=散文である」の宣言、読点は間(ま)の演出になる。
  読点はもともと語のリズムではなく構文の曖昧さを解くための記号なので、見出しには原理的に不要。
  **点を消すのではなく、一文に組み替えるか短縮する**のが正しい対処(句読点は §6 で測る)
- **断定の強さは証拠の強さを超えない。** 聴衆に一人でも専門家がいれば、証拠を超えた断定は当該の
  一文ではなく資料全体の信頼を壊す。逆に、外挿・推定・未確定であることを本文で自ら開示する
  装置は、弱さではなく信頼の源泉として働く。分かりやすさのための言い切りは誠実さに劣後する
- **偽の網羅性を作らない。** 「〜は次の3つ」は代表例のピックであっても全体集合の宣言として
  読まれる。枚挙の構造は内容と独立に「これで全部です」という事実主張を発生させるので、
  代表例なら代表例と書く。同じ理由で見出しは段階の数ではなく変化の方向を語る — 数の強調は
  概念が増えた時点で陳腐化する
- **平易化とは、正確な概念語を平易な説明で包むこと。** 概念語を捨てて言い換えるのは平易化ではなく
  劣化で、詳しい聴衆には一撃で見抜かれ、聴衆が持ち帰る理解そのものが誤ったものになる。正確な
  語で書けば聴衆は後で検索も議論もできる。分かりやすさと正確さは択一ではなく、両立させる
  ワーディングを探す仕事がある
- **術語は説明に溶かさず、持ち帰り語として面に立てる。** 講演の価値の一部は「聴衆がその後の
  会話・検索に使える語彙」を渡すことにある。平易に説明しきると理解は残るが語が残らず、聴衆は
  自分でその話題に戻れない。だから術語は本文の説明とは別に、大きな活字のキーワードとして
  独立して置く
  - **通じない語は日常語へ翻訳する**。馴染みのない語は比喩の効果をゼロにするので、比喩の本質を
    保ったまま置き換える。ただし確立された概念名の原語は、和文を主役に保ったまま添えると
    「分かる人には分かる」層として働く。翻訳(必須)と原語併記(任意の付加)は別の操作
  - **語の解像度は「何の話か一語で分かる」水準まで上げる**。広い語は聴衆が自分の業務に誤って
    引き寄せる。修飾語1語で誤読の分岐を潰せるなら、字数のコストより価値が大きい
- **面の外の文言を面に書かない。** 面に書かれた文はすべて「聴衆に伝えたいこと」として読まれる。
  だから内部運用の注記・検証プロセスの叙述(「一次情報で確認した」)・自己言及ラベル
  (「読まなくてよい」)・作り手の内心は、伝えたいことを薄めるうえに舞台裏を見せる違和感を
  生む。**消すのではなくスピーカーノートへ移す**のが正しい処理
- **聴衆の属性を名指しして語りかけない。** ラベルを面に書くと説得ではなく説教になる。属性への
  適合は構成・語彙・事例選択で織り込むものであって、文字にして突きつけるものではない
- **固有名は業界の粒度まで一般化する。** ピンポイントのカスタマイズは「調べられている」感覚を
  生んで警戒され、聴衆が属する組織の内部事例は内輪ネタになる。**適度に距離のある公開の一次
  事例のほうが、聴衆は自分の状況に当てはめられる**。可視面だけでなく、ノート・HTML コメント・
  配布ファイル名まで揃える
- **出典は逐語引用+一次検証。** 人物の現職・肩書き・日付は学習時点で固定された情報であり、
  間違えばその一点で資料の信頼が壊れる。一次発言の逐語引用+出所明示は最も強い提示形なので
  標準形として扱い、知識境界の外にありうる属性は必ず外部で確認する
- **依頼者本人の資料は素材であって出典ではない。** 出典表記は「外部の権威に依拠している」ことの
  表明なので、依頼者本人の成果物に付けると、自分の資料に自分を引用する不合理と、代作である
  ことの露出が同時に起きる。**出典の作法を杓子定規に適用すると、作法そのものが事故になる**
- **強調は主従を決めてから配る。** 最大の活字は一面にひとつ。二つ大きくすると、聴衆はどちらが
  主張か決められないまま両方を弱く受け取る。「印象的な語」と「本当に持ち帰らせたい文」が
  競合したら、後者を大きくして前者を添える
- **かっこよさは伝達に劣後する。** 文学的な見出しは「一目で何の面か分からない」という単一の
  欠点で他の長所を失う — 見出しの第一機能は聴衆の地図であり、修辞はその次。既視感のある演出も、
  洗練ではなく手抜きとして読まれる
- **依頼者の口述は思考の素材であって、完成文言ではない。** 口語の比喩・例え話は「何を伝えたいか」
  の一次資料だが、そのまま面に載せると口語の緩みと個人的な連想が残る。本質とニュアンスだけを
  汲み、表現は作り手が起草し直す — これは指示の無視ではなく、指示の正しい実装である
- **依頼者が承認した文言は保護する。** 文章の一括改善は良い箇所を平均へ引き戻す作用を持つので、
  「これはいい」と言われた表現は改善対象から外し、保護リストとして明示的に持つ

## 2. レイアウト

- **余白は未使用の情報帯である。** 投影面は固定サイズの希少資源で、空いた余白は「まだ入る」
  という証拠にしかならない。埋める順序は **①伝えるべき情報の充填 → ②それでも余るなら
  フォント拡大**で、装飾では埋めない。順序が重要で、フォントだけ先に上げると溢れ、面だけ
  埋めると小さい活字が増える。余白を許す面は依頼者が明示的に指定した例外としてだけ存在する
  — 規範に例外がないと作り手は不自然な充填をし、例外が暗黙だと規範が緩む
- **読ませる活字の床は投影環境が決める。** 可読性の床は聴衆と投影距離という外部制約から決まる
  ので、レイアウトの都合で下回ってはいけない。重要な内容が小さい活字で書かれているのは、
  **作り手が面の制約に負けた痕跡**として読まれる。収まらないなら情報を削るか面を再設計する。
  小さくてよいのは読ませる気のない情報(出典・注)だけで、ここに「読ませる/副次/出典」の
  階層が生まれる
- **測るのは属性値ではなく実効 px。** SVG 内のテキストは viewBox と描画幅の比で拡縮するため、
  `font-size` に書いた数字は実際の見え方を保証しない
- **拡大と再配置は一つの作業。** フォント拡大は面内の他要素との干渉を必然的に生むので、
  「大きくする」と「重ならないよう改行・位置を調整する」は分離できない。したがってデッキ全体
  への一律 CSS 変更は禁物で、面ごとに余白の充填と同時に適用する
- **タイトルは1行。** 不自然な位置での折り返しは語のまとまりを壊し、内容以前に「調整されて
  いない」ことを露出させる。行末に1文字だけ残る孤立も同族。折れたらフォントを詰めるのが
  正しく、折り返し位置の調整は次善
- **固定物との clearance は実測 px で確保する。** 重なりは内容を誤らせないが、資料の水準を
  一撃で判定させるので聴衆が最初に気づく。とくにフッター・ロゴ・ページ番号のような固定物との
  衝突は、コンテンツ側だけを見ている限り検出できないので独立に測る。テキスト同士より、箱の
  枠線・背景・矢印とラベルの重なりのほうが見落とされやすい

## 3. ビジュアライズ

- **伝達目標を一文で言えない図は捨てる。** 図の説得力は「主役が一つに絞れているか」でほぼ
  決まる。目標が言えない図は、装飾か、作り手が考えていないことの証拠として読まれる。
  **箱を整列させたものは図ではない** — 配置は構成であって主張ではないから
- **面積は情報量に比例させる。** 枠が多いのに情報が薄い図は、その面積を占める正当性がない。
  単純な包含関係は小さく描き、空いた面積には別の切り口(分類と包含を重ねる等)を載せて
  密度を上げる
- **座標は幾何から導出する。** 人は形の不整合を意味より先に検出するので、ふにゃふにゃの線・
  不揃いの山・線から外れた点は内容の信頼性まで疑わせる。注釈マーカーを目分量の px で置くと、
  編集を経てドリフトし、しかも静止画の検証を素通りする。交点・接点は数値で解いて座標にする
- **曲線の形は主張である。** 成長を語る面で線が平坦なら、図が文章を否定している。形・傾き・
  カーブは装飾ではなく主張の一部。ただし合わせる方向は一つで、**主張に合わせて形を誇張するのは
  不誠実** — 主張と形の両方をデータに合わせる
- **分類図の包含関係は厳密でなければならない。** 図は文章より誤りが目立ち、しかも訂正の機会が
  ない。聴衆に一人でも詳しい人がいれば分類の誤りは即座に検出される
- **引用が情報の主成分 — 集めてから組む。** 自前のテキストと自作図だけで組んだデッキは
  必ず薄くなる。明示的な依頼がなくても、面の主張を支える外部資料(一次資料の図・チャート・
  公式ドキュメント・実画面のスクリーンショット)を集める工程を先に置く(SKILL.md 手順3)
- **原典の図の引用は自作図に勝る。** 同じ主張なら一次の図が最も強い。公式チャートに表示モードの
  選択肢があるなら、主張に合うモードを選んで公式のまま貼るほうが自作プロットより上位。
  象徴的なチャートも、切り抜き引用のほうがテキスト要約より強い
- **何を引用するかは聴衆の文脈で選ぶ。** 同じ主張を支える資料が複数あるなら、聴衆に最も近い
  視点のもの(その業界・その組織・その立場の事例)を引く。引用の選定は装飾ではなく
  「自分ごとにさせる」ための設計判断であり、面ごとに理由を言えること
- **画像には読み方を添える。** 画像そのものは装飾で、「何か・どういう文脈で出たものか・何を示す
  図か・どこを見るか」が添えられて初めて論拠になる。出典表記だけでは足りない
- **桁外れの数字は換算で体感化する。** 人は絶対値の桁を体感できない。既知の量への換算・比較
  対象・時間軸上の立ち上がりを添えて初めて数字が感覚になる。数字を大きく書くことは体感化
  ではない
- **色は識別の意味に割り当てる。** 単色グラデーションは順序を示すが識別を殺し、無根拠な多色は
  意味を持たない。色は「何と何を区別させたいか」から決まるので、外部で確立した意味色
  (ブランド色など)を優先し、アクセントを足すなら最小限に留める。「無駄にカラフル禁止」と
  「意味のある色分け」は矛盾しない — 前者は装飾の話、後者は識別の話
  - 割り当てた色は**デッキ全体を貫く共通の色言語**として通す。同じ色が面ごとに別の意味を持つと、
    色は識別に使えなくなる
  - 借用した視覚メタファーでは色と形そのものが意味を運んでいるので、原典の記号性を崩さない。
    崩すとメタファーが機能せず、知っている聴衆には誤りとして映る
- **テキストだけの面は作らない。** 文字だけの面は視覚の仕事をしておらず、聴衆の記憶にも
  残らない。ビジュアルは装飾ではなく理解の主経路なので、ビジュアルが面の主役になる設計を
  既定値にする

## 4. 構成

- **各論の前に地図を渡す。** 初見の聴衆は、全体の中の位置を知らないまま各論に入ると迷子になる。
  用語の全体像と「今回はここを説明します」の宣言を先に置くだけで、以降の説明はすべて位置づけを
  持つ。これは丁寧さの問題ではなく**理解の前提条件**
  - 導入面の目的は分類学ではなく概念定義。「X には広義と狭義がある」は分類の説明で、聴衆が
    求めている「X とは何か・なぜ今それを説明するのか」に答えていない。下位区分は導入の
    主役になれない
  - 未導入の区別語を先に出さない。聴衆はまだ持っていない対比を前提として要求される。動機 →
    未定義のままの探索 → 部分的な成果 → だから命名、の順に並べると語は説明されずに理解される
- **具体を先に、抽象を後に。** 実例で認識を作ってから抽象化すると、抽象が具体の要約として
  受け取られる。逆順にすると、抽象は聞き流されて実例が「例のひとつ」に落ちる
- **枚数は発話時間から逆算する。** 枠の長さではなく実際に喋る時間から決める。1枚あたりの発話が
  重いデッキでは、見積りを面の数ではなく分で持つ必要がある。時間配分は個々の面に任せず中央で
  設計して各面へ転記しないと合計が合わない。構成の増減は終盤に一括で行う — 構成をいじりながら
  中身を上げると削除の判断材料が消えるので、削除候補は印を付けて可視のまま保持する
- **深掘りは Appendix へ逃がす。** 本編の構成が確定したあとも「書きたい内容」は増え続ける。
  本編から参照しない付録に置けば、本編のページ構成と時間配分を不変に保ったまま情報を追加
  できる。ただし置くだけでは使われないので、**どの操作でその面へ飛ぶか**をノートに書く
- **面と面の接続語は実文言で裏取りする。** 各面を個別に改善すると、面をまたぐ語の受け渡しが
  静かに壊れる。前の面が渡した語を次の面が受けているかは、実際の文言の一致でしか確認できない

## 5. 表記の一貫性

送り仮名・カタカナ長音・数値と単位の間隔・敬体と常体のような表記のゆれは、正解が一つに決まらない
代わりに**デッキ内での不統一だけが目に見える**。だから個別の規則を覚えるのではなく、デッキ内で
一貫させることに労力を割く。

迷ったら依頼者の資料の表記に従う。依頼者の組織には既に表記の慣習があり、それに合わせたものが
最も違和感がない。

## 6. 検証との接続

この文書の規範のうち、次のものは機械で測れる:

- タイトルの句読点(§1)
- タイトルが1行に収まっているか(§2)
- 読ませる活字の床 — 属性値ではなく実効 px(§2)
- 固定物との clearance(§2)
- 面の外の文言(作業ログ・自己言及ラベル・聴衆ラベル)の混入(§1)

`verify.mjs` の `--strict` / `--font-floor` がこれらを検査する。手順と読み方の正典は
[VERIFICATION.md](VERIFICATION.md)。

残りは測れない。「違和感がある」「一目で何の面か分からない」「図が何も言っていない」は機械ゲートの
外側にあるので、**実物・全面・等倍の目視パスを機械ゲートと並走させる**。機械ゲートは網であって
レビューアーではない — 網の目を細かくしても違和感は捕まらない。
